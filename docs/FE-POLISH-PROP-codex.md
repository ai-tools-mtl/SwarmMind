# SwarmMind 前端显示效果优化提案（Codex UI/UX 只读评审）

评审日期：2026-10-28。对象：hub/node 两端 index.html、app.js、style.css，共 6,742 行；另对照 AGENTS.md、SPEC 六.五/七、INTERACTION 反馈要求、FE-PLAN v3。

本提案只新增本文件，未修改仓库、既有临时文件或运行配置。结论来自源码审阅与只读静态比对，未启动服务、未操作真实任务、未作浏览器截图/交互实测；布局溢出、原生菜单外观等需按下列标准在实施后验证。文中“验收”均为未来要求，不表示本轮已经通过。

评审判断：灰阶体系、任务异常分级、结果与日志的材质层级已经成立。主要粗糙感来自**同样的动作在两端反馈不同、长列表读到一半失去位置、表单状态缺口，以及共用 token 未覆盖到控件细节**。优先补齐这些，再做有限的排版收口。

分级：P1＝必须修（硬约束偏离、关键状态/可达性问题、白名单外同类交互漂移）；P2＝建议修（扫读与反馈质量）；P3＝可不修/后续优化。各条同时给出文件:行号；路径简写 H=internal/hub/web，N=internal/node/web，均相对仓库根目录。

硬约束原样保留：Apple 灰阶工具视觉；accent/heat/live/danger 四个语义家族；表格内文字至少 12.5px；玻璃限 topbar/toast；动效用于反馈。已获 SPEC 豁免的功能和关闭生命周期差异不作为缺陷强制拉齐。

## 一、视觉层级与长列表扫读

### V01｜收回 FINAL 消息的第五种语义色

【现状】H/style.css:455 为 `.msg-final` 使用 `#d9a441` 金色竖线和金色底；H/app.js:2682 由 agent 消息的 `FINAL:` 前缀触发。

【问题】明确突破四色预算，也重新引入彩色装饰竖线；候选文本获得了近似“已经定版”的视觉权威。

【方向】用灰阶底面、字重和“收敛候选 · 待定版”文字标识强化；沿用现有状态事实，不把 FINAL 前缀升级为已批准结论。验收：该组件无四色家族外色值、无彩色竖线，普通消息/候选/系统注记可通过文字与版式区分。

【优先级】P1（必须修）。

### V02｜字号下限要覆盖表格子元素

【现状】H/style.css:117、N/style.css:88 的 badge 使用 11.5px；表格主体虽为 12.5px，状态/来源徽标仍覆盖字号。H/app.js:1218 的能力描述是 td 内 small；H/style.css:169 使它也使用 12.5px。N/app.js:1147 的 node 配置表还含 11px `.readonly`（N/style.css:260）。

【问题】“表格字体达标”只在主体成立，最需要扫读的状态反而更小；不能以全局 token 值替代最终计算字号验收。

【方向】表格上下文统一约束 badge、readonly、说明与操作文字下限，保留表格外微标签档位。验收：任务、节点、配置、工作单、Markdown 表格内所有实际可见文字 computed font-size ≥12.5px；200% 缩放不裁字。

【优先级】P1（必须修）。

### V03｜让关键小字可读，避免整块透明度削弱信息

【现状】两端表头/td small 用 ink-4（H/style.css:163、169；N/style.css:113、119）；零计数 chip opacity .55（H:140，N:102），停用渠道整卡 opacity .62（H:428，N:278）。heat=#ff6b00 亦用于小号异常文字。

【问题】时间、任务 ID、停用渠道的编辑/删除操作都随弱化一起变淡。按源码色值计算，ink-4 对白底约 3.62:1，heat 对白底约 2.86:1；这里只是纯色对比，带底色/透明度的实际组合需另测。

【方向】关键可读信息至少使用满足对比度的现有灰阶；同一 heat 家族可有深色文字档，保持语义预算不变。停用只弱化状态/表面，不整卡降透明度。验收：常规小字对实际背景至少 4.5:1；零计数仍能看清且可选择；停用渠道按钮维持正常辨识度。

【优先级】P2（建议修）。

### V04｜任务列表应先回答“这是什么任务”

【现状】hub 任务首列是 agent 名+任务 ID（H/app.js:1673）；node 最近任务把幂等键截取 24 字符放在“任务”列（N/app.js:873），详情列表则主要列目标与任务号（N:1478）。

【问题】同一个 agent 连续执行十项工作，行与行几乎同貌；幂等键不能代替人可理解的任务摘要，用户需逐行打开确认。

【方向】在既有数据允许时补一行任务描述摘要，agent/机器仍清楚常驻；无摘要则如实留空或使用“未提供描述”，不由 ID 猜内容。node 最近任务列名与内容一致，恢复密钥进详情。验收：同 agent 的 20 项不同任务可直接区分；摘要最多两行，完整文本在详情可查，技术 ID 可选择复制且不丢失。

【优先级】P2（建议修）。

### V05｜宽表和抽屉表格分别定义滚动归属

【现状】hub 所有 th 全局 sticky/top:84px、table-wrap overflow:visible（H/style.css:161、163）；工作单抽屉仍复用普通表格（H/app.js:3051、3060），只有 Markdown 表头显式取消 sticky。node table-wrap overflow:auto 且表头不吸顶（N/style.css:111、113）。

【问题】页面表头硬编码高度未跟随 topbar 折行；抽屉内部表头也获得 84px 偏移。长任务 ID、多列工作单在窄视口可能撑出主页面。两端长表阅读记忆不同。

【方向】页面列表保留主滚动契约，表头偏移跟随实际 topbar；抽屉表格单独规定不吸顶或贴抽屉滚动容器顶部。只在宽度不足的区域提供横向滚动，并解决 overflow 对 sticky 的影响。验收：1440/1024/680/390px、200% 缩放下无整页横向溢出；上下滚动无遮挡/悬空表头；同类双端表格采用同一策略。

【优先级】P1（必须修：同类表格漂移；具体溢出待浏览器验证）。

### V06｜让运维列表成为稳定阅读面

【现状】hub 资源变化后 render 重建 #app（H/app.js:886、949）；筛选 input 每键重绘并只按 id 恢复焦点（H:1049、3754），多个 select 没有 id。node 轮询除 cfgEdit 外可整页 render（N:638、747），本机服务 select input 也重绘（N:1984）。

【问题】保存了值不等于保存交互：中文组词、选择区、打开的原生菜单、手动展开的 details 和键盘位置仍可能被打断。node 派单表单与列表共页，任务变化会波及正在填写的表单。

【方向】把稳定表单壳与列表数据区分开，数据更新局部 diff；输入法组合期不重建输入节点。列表新增任务不要无提示地挤动正在阅读的行，可显示待更新提示并由用户应用。验收：输入中文、打开下拉、展开配置详情并跨越三轮有数据变化的轮询，节点身份/焦点/选择/展开状态保持；不以重建后回填作为终解。

【优先级】P1（必须修）。

### V07｜区分“没数据”“未加载”“读失败”

【现状】hub 群列表加载除 503 外失败直接返回（H/app.js:854），空数组进入“还没有协作群”；新开工作单抽屉分区为空、首次读取失败静默（H:2955、3003）。node loadAll 使用响应体缺省空数组且轮询失败静默（N:580、645）。hub 新鲜度在全部资源从未成功时隐藏（H:815）。

【问题】用户可能把不可达误认为真空列表；空白抽屉像按钮没有响应。仅首屏“连接中”不能承担各资源后续失败反馈。

【方向】建立首次加载/成功为空/有数据/陈旧数据/失败五态；读失败保留旧内容，提供就地重试与最后成功时间，资源名用中文。验收：首次全失败、局部失败、断网后恢复分别有确定画面；失败不显示“还没有”，旧数据不清零，首开抽屉 300ms 内有标题、关闭和加载提示。

【优先级】P1（必须修）。

### V08｜控制空态与说明文案的垂直成本

【现状】两端 `.empty` 统一上下 56px 留白（H/style.css:236，N:207）；无通知渠道的嵌套空态（H/app.js:2521，N:1296）和 node 服务卡长说明、详情、能力配置纵向堆积（N:988、1131）。

【问题】局部空态也有首用大页面的体量；长页面里常规运行规则与当前要做的动作竞争首屏空间。

【方向】区分整页首用空态和卡内空态；卡内只保留一句说明与一处明确动作，规则按需展开；已有通知优先位置保持，不用重排页面来绕过信息密度问题。验收：1280×800 下空通知卡不会占据大半内容视口；三项服务可扫到状态和主要操作；表格字号不缩小换空间。

【优先级】P2（建议修）。

## 二、交互反馈完整度

### I01｜补齐 node 弹层的键盘闭环

【现状】hub 有背景 inert、Tab 循环、Esc 和焦点返回（H/app.js:1741、1765、3825）；node 通知 modal 虽有 dialog 属性，仍无背景隔离、Tab trap/Esc；配置抽屉是普通 div、关闭为无名 ×（N:1067、1093、1352、2002）。node 任务行无 tabindex（N:873、1478）；hub 工作单行有 tabindex 却只有任务行键盘处理（H:2924、3852）。

【问题】键盘可走到遮罩背后；部分可点行无法按预期打开，视觉焦点和操作位置脱节。ARIA 声明本身不能补足行为。

【方向】同家族补齐入层焦点、背景隔离、Tab/Shift+Tab、Esc、返回目标以及关闭按钮可访问名称。node 可继续使用已豁免的直清，不以新增出场动画为前置条件；hub 工作单行补等效键盘路径。验收：仅键盘完成开层→填写→取消/保存→回触发点；背景不能被误触；原行被刷新替换时返回稳定页签或列表入口。

【优先级】P1（必须修）。

### I02｜让 focus、hover、pressed 各自有明确职责

【现状】按钮有 hover/scale active，原生控件有 focus 环，但多数按钮/可点行仅依赖浏览器默认焦点（两端 style.css:35 起）；hub 只有 help-dot 定义 focus-visible。开关仅 aria-label，无 role=switch/aria-checked（H/app.js:2533，N:1308）；筛选与 toggle 主要靠 CSS 类表示选择。

【问题】不同元素的键盘焦点辨识不均，辅助技术无法直接获知筛选选中和开关开闭。不能把“没自定义 focus”直接说成“完全无焦点”，当前默认样式仍可能显示。

【方向】统一 focus-visible 规则，按钮/行/summary/开关均可见；筛选用 pressed 或适当选择语义，开关传达 checked。验收：Tab 全程可追踪；hover 与选中不混淆；屏幕阅读器可报告开关状态与当前筛选；禁用按钮不发生按压位移或误导性 hover。

【优先级】P2（建议修）。

### I03｜所有写动作反馈应就地出现

【现状】hub token 创建/账户保存只有 busy Set，无按钮标签更新（H/app.js:2479、3354）；密码登录/初始化不同于令牌登录，未给对应按钮 loading（H:1097、1112、1138）。node 测试渠道只禁用不改文字（N:1377）；hub 工作单动作仅 disabled（H:3107）。

【问题】请求慢时像点了没反应；禁用状态与“当前正保存”不等价，容易诱发其他入口重复操作。

【方向】就地提供动作动词的进行时，锁定同操作，保留按钮几何尺寸；完成/失败恢复。验收：人为延迟 2 秒，点击后 300ms 内该操作显示“保存中/验证中/发送中”；同操作只发一次，失败后可继续，其他无关读操作仍可用。无需全站加 spinner。

【优先级】P2（建议修）。

### I04｜错误和结果未知不能只在短 toast 里存活

【现状】两端大量保存/测试/取回错误仅 toast；hub 3400ms、node 3200ms 自动消失（H/app.js:1042，N:1860）。hub 工作单续派网络异常仅 toast，随后按钮恢复（H:3200）；node cfgSave 用 alert（N:925）。

【问题】长错误读不完；关闭提示后找不到原因。尤其“结果未知”需要持续核对，瞬时提示弱于风险语义。

【方向】toast 只简短报结果，原操作区保留失败原因与下一步；结果未知保留请求上下文并以核对事实/同键恢复为主入口，避免暗示立即新建尝试。验收：提示消失后仍能看到失败与重试路径；未知态与明确拒绝区分，不清空草稿；不要求后端新增能力。

【优先级】P1（必须修：结果未知反馈）；普通可重试错误为 P2。

### I05｜让危险操作在两端有相同的确认语言

【现状】hub 删除渠道用 danger 和 slim modal（H/app.js:2540、3331）；node 删除渠道用 off-btn+confirm，配置保存失败用 alert（N:1315、1389、925）；node CSS 未定义 danger/warning。

【问题】同一删除动作一端可辨识、一端像普通按钮；系统确认框与产品弹层混用，按钮词、对象与后果难以一眼对应。

【方向】通知删除双端复用居中确认形态与危险描边，明确对象、不可恢复后果与“删除/取消”。node 配置错误改就地反馈，其他确认流程逐项复用该家族，不盲目加额外确认。验收：同渠道两端删除前后截图同构，Esc/取消无副作用；删除失败仍能重试。另修 H/app.js:3344 的失败分支未恢复删除按钮 disabled/文案问题。

【优先级】P1（必须修）。

### I06｜通知面板应像可收起的操作面

【现状】H/app.js:2622 仅 hidden 切换；bell 按钮无 expanded/controls（H/index.html:15）；Esc 只处理主弹层。面板开启时 paintBell 每轮 innerHTML 重建（H:2593），外部点击若先命中其他 data-act 会在收起检查前返回（H:3731）。通知点击仅标已读（H:3351）。

【问题】展开状态不清楚、键盘收起缺口、正在操作的条目可能因刷新换节点；通知标题像任务入口，但实际只读标记，没有清晰去向。

【方向】补展开语义、Esc/外点关闭、合理焦点返回、按条目 diff；明确“标已读”与“查看任务”两个意图，有任务 ID 且能力允许时提供明确查看入口。验收：打开后跨三轮无变化刷新焦点不丢；点击页面其他操作面板正确收起；读取失败保留旧通知并显示重试，测试消息不伪造任务入口。

【优先级】P2（建议修）。

## 三、下拉菜单与表单控件

### F01｜原生下拉保留，但选项之外必须提供决策信息

【现状】hub agent 选项只留名称、描述放 option title（H/app.js:2167）；选后摘要仅机器/agent/角色（H:2186）。node 选后有描述与权限（N:1430），但总览管家选择把整段描述塞进 option（N:847）。失败原因选项又是长句（H:1662）。

【问题】option title 的呈现受平台影响，不能作为理解能力的唯一入口；同名能力、长失败原因会挤压选择效率。描述长短策略在不同控件间不一致。

【方向】少量选项继续原生 select，统一边界/字号/禁用说明；短选项名称+分组，描述/权限/执行位置在选后摘要常驻可读。选项多到难找时再提可搜索 combobox，沿用既定分组，不默认重写所有原生菜单。验收：macOS Safari/Chrome 键盘选取、长名称、离线/无能力/未选机器均清楚；无需 hover 也可判断选中能力能做什么；不把整个角色长句塞进选项。

【优先级】P2（建议修）。

### F02｜表单错误指向具体字段

【现状】派发和渠道校验多使用 toast（H/app.js:2321、2551；N:1489、1326）；端口只用 inputmode=numeric（共享通知表单 H:512），多个 required 字段所在表单通过按钮动作而非正常 submit 提交（H:471、487）。

【问题】required 不保证动作路径触发浏览器校验；错误消失后字段没有痕迹，用户要重新猜是哪个值有问题。

【方向】提交时校验并滚动/聚焦第一个错误字段；字段旁保留短错误、正确后清除，aria-invalid/describedby 关联。端口、邮箱、URL 按当前后端接受范围提示，不自行收窄协议。验收：空名称、无执行者、非法端口/地址与服务端拒绝都有落点；不清空其他值；错误不只靠红色表达。

【优先级】P2（建议修）。

### F03｜切换通知类型后保留尚未提交的草稿

【现状】两端 nf-type change 调用 nfRepaint(type,'generic',{})（H/app.js:3797；N:2011）；格式切换保存 URL/header，切到另一类型再回来则用空 secrets。

【问题】比较邮件与 webhook 的过程中，已填写地址/账号可无提示消失；局部渲染保护了名称，却未保护整份用户意图。

【方向】按类型暂存当前编辑会话草稿；类型切回恢复，密码保留在当前会话内且遵循现有掩码语义，关闭即清。验收：邮件→webhook→邮件、generic→feishu→generic 往返不丢可支持字段，名称/事件不变；不在浏览器持久存储新增秘密。

【优先级】P2（建议修）。

### F04｜把结构性配置变更的“下一步”露出来

【现状】node 新增 agent 只追加未命名行后重绘，未打开编辑（N/app.js:1897）；删除先移除副本，需要另保存全部才落盘（N:1903）；抽屉保存与表格保存全部并存（N:1019、1107）。

【问题】点击新增后像只多了一条空记录；删除后容易以为已生效；“未保存/已写盘待重启/已运行”三个事实缺少统一视觉摘要。

【方向】新增直接进入同家族编辑抽屉；页面显示待保存数量、待重启状态和对应下一步；抽屉取消要明确处理刚新增空行，避免遗留脏记录。验收：新增→取消不留空项；删除后清楚标示“待保存”，保存后“待重启”；无需阅读长 footer 才能判断实际状态。

【优先级】P2（建议修）。

### F05｜复选框和多按钮行不应继承文本输入布局

【现状】hub 建群主持 checkbox 使用行内 flex label，却仍继承 input width:100%/display:block（H/app.js:2867；H/style.css:148），未用现有 checkline。node 配置底部三按钮用不换行 `.row`（N/app.js:1019；N/style.css:81）；长任务指令参数 pill 使用 nowrap（两端 `.cmd-args code`）。

【问题】控件可挤占说明宽度，窄视口长动作/路径可能越界；这些是组件局部布局问题，增加页面留白解决不了。

【方向】checkbox 统一复用 checkline；动作组按语义换行；参数边界仍独立显示，但单个超长参数允许安全换行/局部滚动并可完整复制。验收：390px、200% 缩放，checkbox 保持正常尺寸且说明可读；三操作均可见；长路径/单参数不撑破抽屉。

【优先级】P2（建议修，溢出待实测）。

## 四、动效与过渡

### M01｜统一 toast 反馈，减少消息消失时的突兀

【现状】hub 顶部玻璃胶囊、show 过渡 320/220ms（H/style.css:319，H/app.js:1042）；node 底部实黑胶囊、hidden 直显直消（N/style.css:237，N/app.js:1860，N/index.html:19）。

【问题】跨端相同反馈看起来像两套产品；node 的即时消失缺少状态结束提示。背景材质差异不是现有 SPEC 的关闭直清豁免。

【方向】双端采用同一 toast 位置、材质、进入/退出与停留规则，复用已定召唤层语言；错误长内容按 I04 留在原位。验收：短反馈双端同屏对比一致，不遮挡 topbar/主动作；连续消息不闪白、不排成长队，减弱动效时只做淡变。

【优先级】P1（必须修：同类组件漂移）。

### M02｜仅补“由用户召唤”的小面板过渡

【现状】hub 通知面板与新消息浮标 hidden 切换（H/app.js:2626、2803）；已有主弹层进入 400ms、退出 260/280ms，抽屉刷新使用分区机制。

【问题】铃铛面板的出现/收起相对其他召唤层生硬；但为每条新数据加过渡会破坏运维扫读。

【方向】通知面板可用现有短时长档做 opacity 为主的过渡；浮标只轻淡入，数据行/数字/状态更新不播放入场。验收：按铃即可交互，不等待动画；快速开关不残留可聚焦隐藏内容；轮询不重播。details 展开默认保留原生即时反馈，除非浏览器走查证明跳变影响定位，再单独提案。

【优先级】P3（可不修）。

### M03｜补齐减少动效/透明度偏好

【现状】两端 reduced-motion 主要覆盖召唤层（H/style.css:372，N:224），running 点仍持续 pulse；按钮缩放、switch 位移仍保留。hub 页内跳转强制 smooth（H/app.js:3146）；node 没有 reduced-transparency/contrast:more 分支。

【问题】用户主动减少动态后，列表仍有多个持续脉冲；双端系统偏好降级不一致。

【方向】该偏好下 running 使用静态点、按钮取消缩放、switch 取消滑动但保留状态变化，页内定位用即时滚动；node 对齐已有透明度/增强对比降级。默认模式不额外增加动画。

验收：系统三种偏好分别开启，双端可读可操作；reduced-motion 下无持续 pulse、位移或强制 smooth，必要加载可用静态“加载中”文字。

【优先级】P2（建议修）。

## 五、字体、数字与时间排版

### T01｜等宽数字已经部分具备，补齐列对齐与表外数据

【现状】两端 td/metric/mini-stat 已有 tabular-nums（H/style.css:97、165、337；N:79、115、245），并非全站缺失；小字几乎被 td small 一律切到 mono。分页、chip 计数、通知时间、抽屉时间并非统一数字上下文（H/app.js:1634、2608、1894；N:1822）。

【问题】“等宽数字”不等于数值列对齐；现在各数字列左对齐。中文能力描述跟随 td small 使用等宽英文字体回退，也缺少类型区分。

【方向】采用下表范围，靠字段类型指定，避免所有 small 一刀切。验收：1/8/88/100、分页 9→10、时刻改变时宽度稳定；数量列统一右对齐（进度比可固定宽居中），日期列统一格式且不拆成多行；中文说明仍为正文家族。

【现状】抽屉 shared fmtUTC 一致；hub 列表 fmtTime 以 ISO 字符串切片（H/app.js:1037），node 列表只显示本地时分秒（N:706、1478），通知渠道时间 hub 用分钟级字符串，node 用本地完整日期（H:2542，N:1317）。

【问题】历史跨日只看时刻易误读；并排查看中心端/本机像时间错了。SPEC 明确全站非抽屉时间迁移另批，因此不把已有范围裁决当新增违约。

【方向】作为独立排版批次统一非抽屉时间口径，优先显示日期+时刻并标时区，完整时间悬停/详情可查；解析时间后格式化，零值/非法值用“—”。验收：跨日、非 UTC offset、零值、非法值分别覆盖；同一任务两端可直接对照，不修改存储/API 时间。

【优先级】P2（建议修，已有延期裁决）。

## 八、反提案

以下常见做法不应进入本轮实施：

1. **全站玻璃拟态**：卡片、下拉、抽屉、通知面板加 blur。玻璃严格只给 topbar/toast，正文保持实底可读。
2. **全员微动效**：hover 每卡浮起、数字翻牌、列表行轮询淡入、状态弹跳、持续闪光。数据面应稳定；保留既定召唤层动效，群卡既有 lift 无需扩大适用面。
3. **渐变横幅与欢迎大屏**：占据首屏但不增加运维判断信息；不增品牌hero、问候语或彩色统计装饰。
4. **彩色大按钮与新增成功/管家专属色**：主操作仅局部有主次；灰pill体系保留。删除采用现有danger；FINAL不用金色、管家不引入紫色。
5. **用缩小字体解决密度**：表格包括badge/按钮/说明全部不低于12.5px，先减少重复说明、无用列与空态占高。
6. **把所有原生下拉重做成自绘菜单**：少量选项原生控件更省认知；只有规模和检索成本支持时才引入可搜索组合框，并完整验收键盘与焦点行为。
7. **全表彩虹状态、条纹和多重描边叠加**：沿用灰阶主体，异常靠文字、排序入口与既有语义色；不通过提高每行噪音寻找层级。
8. **强求双端每个页面完全相同**：尊重SPEC能力白名单；统一共有组件与真实语义，node不增加假取回/核对/全网管理入口。
9. **拿动效修刷新问题**：整页重建后再淡入、保存草稿后重新灌DOM，都不能替代稳定节点与局部更新；不要把白闪磨成渐变闪。
10. **把错误全塞进toast或反复弹确认**：长错误和未知结果就地留痕；可逆普通动作不额外增加确认层，危险确认必须讲清对象与后果。
