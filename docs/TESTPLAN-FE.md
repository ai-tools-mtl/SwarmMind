# SwarmMind 前端优化测试计划（TESTPLAN-FE v1）

> 本文件是 FE-PLAN v3 的验收规程本体。用例固定 ID，每例含准备/操作/断言/超时/清理。
> 执行方式：独立会话逐条执行并输出逐条结果；必测项 SKIP 不计为通过。
> 登记入口：docs/archive/FE-PLAN-v3.md（FE-PLAN v3，已归档）。

> 本文保留基础控制台用例；新增 Work、任务可见性和派发建议按相应 TESTPLAN 专项执行，不以旧页面数量限制当前实现。

## 通用约定

- 环境：使用临时配置、独立 data_dir 与空闲端口启动本地测试实例；构建与单测先通过。远程部署或真实实例操作另行授权，不把部署命令作为默认测试准备步骤。
- 工具：Playwright（chromium，1440×900）；`route()` 拦截 mock 延迟/失败
- 断言口径：PASS 需逐条给出截图或 evaluate 返回值证据；SKIP 需注明原因且不计入通过数
- 计数锚点：`.metric`≥3、`.chip-link`===8、`[data-act]`/`#id` 全集不破坏

## P0 用例（数据与交互可靠性）

**FE-01 旧响应晚到不覆盖**
准备：拦截 `/api/v1/tasks`：首次响应为数据 A（含特定任务），随后触发刷新的新请求 mock 为数据 B（任务集不同，可页面区分）延迟 300ms，而旧请求 mock 延迟 3s 后返回数据 A。
操作：等待旧响应晚到。
断言：3.5s 后页面任务列表显示的是数据 B（新请求的任务集），未被旧数据 A 回滚覆盖；不依赖内部字段断言。
超时 8s。清理：解除 mock。

**FE-02 单资源失败不阻断**
准备：mock `/api/v1/nodes` 返回 500，其余正常。
操作：等待一个轮询周期。
断言：任务列表正常渲染（tasks 新鲜度时间更新）；顶栏新鲜度显示 nodes「（陈旧）」或该资源独立标记；页面无空列表闪现。
超时 10s。

**FE-03 挂起超时标陈旧**
准备：mock 全部数据接口挂起不响应。
操作：等待 13s。
断言：12s 后顶栏出现「数据更新于 HH:MM（陈旧）」类标记；旧数据仍在页面（未被清空）。
超时 20s。

**FE-04 设置页进页填写保护**
准备：拦截 `/api/v1/auth/tokens`（实际路径，与 app.js loadTokens 一致）延迟 3s，route 回调登记命中标记；未登录缓存清空后登录直达设置页。
操作：延迟期间在修改密码表单输入新值。
断言：route 命中标记为真（确认拦截了正确接口）；加载完成后输入值仍在（表单未被重建清空）；账户信息与令牌列表正常更新。
超时 8s。

**FE-05 设置页轮询保护**
准备：进入设置页待加载完成。
操作：修改密码表单输入值→拦截下一次轮询的 `/api/v1/tasks` 响应注入确定变化（任务列表新增一条 mock 任务）→等待该变化渲染。
断言：任务列表出现注入的新条目（证明轮询命中且数据提交、重绘发生）；同时设置页输入值仍在（免整页重绘豁免生效，区分「没重绘」与「重绘但保护了」）。注：令牌列表不在轮询范围（pollTick→loadAll 不含 loadTokens），不作为变化注入点。
超时 15s。

**FE-06 设置页加载失败态**
准备：拦截 `/api/v1/auth/tokens` 返回 500（route 命中标记）。
操作：进入设置页。
断言：route 命中标记为真；表单可用（不因加载失败永久禁用）；出现错误提示与重试入口；解除 mock 后点重试→正常加载。
超时 10s。

**FE-07 抽屉草稿保持**
准备：存在一个 needs_review 任务（保持该状态不变——核对表单仅在此状态渲染，app.js:994，状态变更会撤掉被测表单）。
操作：打开详情抽屉→核对依据 textarea 输入「E2E 草稿」→点击抽屉内非编辑区（如标题）→拦截下一次轮询的该任务响应，在保持 state=needs_review 不变的前提下修改可见字段（如 result.final_answer 注入新文本）→等待变化渲染。
断言：最终答复区已更新为注入的新文本（证明重绘发生）；textarea 草稿值仍在（证明重绘保护了草稿）。
超时 15s。

**FE-08 草稿任务隔离与跨关开**
准备：两个 needs_review 任务 A/B。
操作：A 抽屉填草稿→关闭→开 B 抽屉（textarea 应为空）→关闭→重开 A。
断言：B 无 A 的草稿；A 重开后草稿仍在。退出登录→admin 重登→A 草稿不跨会话继承（内存态预期清空）。
超时 20s。

**FE-09 忙态恢复与防重复提交**
准备：存在可取消的在途任务；首次取消拦截为延迟 800ms 后 500（失败路径）。
操作：点取消→等失败→按钮应恢复；解除失败 mock 改为延迟 800ms 后 200（成功路径）→点取消→**在 800ms 窗口内再点 2 次**。
断言：失败后按钮恢复可用；窗口内连点仅发出 1 次请求（route 计数）。
超时 15s。

**FE-10 焦点循环与背景隔离**
操作：打开任意弹层→连按 Tab 15 次。
断言：焦点始终在层内（含顶栏 #logout 在内的背景全部不可聚焦）；`aria-labelledby` 指向层内标题。
分支 A（触发元素存活）：Esc 关闭后焦点回到触发元素（如打开抽屉的任务行或其语义等价锚点）。
分支 B（触发元素失存）：打开抽屉后等待轮询重建使触发行消失→Esc 关闭→焦点回到侧栏当前页签按钮且可见可操作。
超时 15s。

## P2 用例（层生命周期与动效）

**FE-11 关闭 A 后 280ms 内开 B**
操作：打开任务抽屉 A→Esc→立即（<100ms）点击另一任务开 B。
断言：B 正常打开完整渲染；A 的延迟清理不影响 B（B 存活 >2s）；无 console 错误。
超时 10s。

**FE-12 关闭中重开同层**
操作：打开抽屉→Esc→立即重新打开同一任务。
断言：抽屉正常打开；无动画错乱（最终态 opacity:1 transform:none）。
超时 10s。

**FE-13 连续 Esc 无残留**
操作：先打开一个抽屉（确认层处于 open）→连续按 Esc 5 次。
断言：`#layer` 无可见层、无可聚焦元素；页面功能正常。
超时 10s。

**FE-14 关闭动画期页面可点**
操作：打开抽屉→Esc→立即（50ms 内）点侧栏「派发」。
断言：页面切换成功；无对层下内容的误触（无任务提交/状态变化）。
超时 10s。

**FE-15 向导节点恒定**
操作：打开接入向导→Step1 填 ID→下一步→下一步。
断言：步进前后 `.modal` 为同一 DOM 节点（evaluate 比较节点引用）；E06 既有断言继续通过。
超时 15s。

**FE-16 reduced-motion 降级**
准备：Playwright `emulateMedia({ reducedMotion: 'reduce' })`。
操作：打开/关闭弹层。
断言：无位移动画（computed transform 无 translateY/scale 过渡值）、过渡时长 ≤250ms；`prefers-reduced-transparency` 与 `prefers-contrast:more` 分别模拟→玻璃转实白/边框增强。
超时 10s。

**FE-17 群消息回看**
准备：测试群通过脚本连续发送 30 条消息（确保内容区实际溢出可滚动）。
操作：向上滚动到中部（scroll 验证 scrollTop>0 且未到底）→注入 1 条新消息（第二上下文发送）。
断言：视口不跳底；出现「有新消息」浮标；点击浮标回到底部。
超时 15s。

**FE-18 sticky 表头**
准备：确保任务列表 ≥40 行（不足则 mock 注入或用历史数据环境）。
操作：滚动页面主滚动条至列表中部（window.scrollY 明显>0，验证 .table-wrap 未形成独立内滚动）。
断言：表头吸顶（boundingBox top 接近视口顶或主滚动参照位置，偏差 ≤2px）；表头背景 computed background 为不透明色（alpha=1，无内容穿透）。
超时 10s。

## 任务筛选与导航统一（TASK-nav-filter-20261026 终审必修4 增补）

对应 tests/e2e-console.mjs 自动条目（hub 模式 `node tests/e2e-console.mjs`：E-NAV/E20/E20x/E20b/E20c/E-401；node 模式 `E2E_BASE=<node local API> local_token=<本机管理令牌> node tests/e2e-console.mjs`：N01/E-NAV3/N02/E-N1/E-N2/E-N3）。以下为交互态逐条机械步骤（深层走查层，逐态截图留证）：

**FE-19 hub 目标机器筛选交互态**
准备：hub 已登录，任务页存在 ≥2 台不同 target_node 的任务。
操作：`aside nav button[data-page=tasks]` 进任务页 → 展开 `select[data-f=node]` → 选中一台机器 → 截图。
断言：选项来自快照去重；行全部命中所选机器；select 选中值回填（控件值与筛选一致，无「显示全部实际在筛」假状态）。
超时 10s。

**FE-20 hub 零命中空态 + 导出同源**
操作：`select[data-f=node]` 选中一台机器 → 点 `[data-act=export]` 捕获下载并解析（验证同源过滤）→ 叠加 `input[data-f=trace]` 填不存在 ID → 截图零命中空态 → 点 `[data-act=clear-filters]`。
断言：导出 JSON 仅含所选机器行（同源过滤，先导出后清除，避免清除后导出失去筛选约束无法验证）；空态含「没有符合筛选的任务」+「清除筛选」；清除后 trace 与机器 select 双复位、列表全恢复。
超时 15s。

**FE-21 node 来源筛选三态**
准备：node 令牌门登录（local_token 环境变量），任务页有混合来源数据（不足则本机派单一枚 + hub 下发一枚）。
操作：依次点击三枚来源 chip（全部/本机派单/hub 下发），各截一帧；再选一个来源后翻「加载更早的任务」截一帧。
断言：chip 选中态显性 + 计数正确；留痕行计入「本机派单」；零命中出「没有符合筛选的任务」+「清除筛选」且「加载更早」仍可点；footer 激活筛选时显示「命中 X 条；筛选作用于已载入的 N / 共 M 条」（三数分离）。
超时 10s。

**FE-22 node 筛选跨轮询/翻页/登出**
操作：选中「hub 下发」→ 等 6.5s（跨轮询）→ 点「加载更早的任务」→ 点 `#logout` 登出 → 令牌门重登 → 回任务页。
断言：轮询与翻页后 chip 选中态与筛选结果保持；登出→再登录后「全部」chip 选中（S.tf 会话边界重置）。
超时 20s。

**FE-23 登录页指纹回归（hub）**
操作：登录 → `#logout` 退出 → 再登录 → `context.clearCookies()` 等轮询 401。
断言：两次回登录页均出现登录表单（`.login`），无业务 DOM 残留；对应 e2e E16/E17/E-401。
超时 25s。
