# P4 观察期细则（草案 v1，待伦哥确认后启动）

> 依据：PLAN.md Gate 修订「工程验收全绿 + 14 天真实使用观察期」；PRODUCT-DIRECTION-v2「观察期在工程验收全绿之后开始，最低任务量、阻塞判定标准、中断后是否重新计时，开工前另行定义」。本文件即该细则。

## 1. 起算与时长

- 确认日：伦哥回复确认本细则之日。
- 起算：确认日次日 00:00（本地时区）起，连续 **14 个自然日**。
- 预计窗口：确认后第 15 日早晨出 Gate 结论。

## 2. 最低任务量（真实性门槛，防挂机凑数）

- 14 天内经 SwarmMind（hub 派单 / MCP / 群聊）派发的**真实任务累计 ≥ 14 个**（平均每天 1 个，允许波动）；
- **有使用记录的天数 ≥ 10 天**（当天有 ≥1 个真实任务即算）；
- 任务应为真实工作（编码/巡检/文档/对账类均可），验收类 echo 任务不计入。

## 3. 记录方式

- 每日一行写入 `docs/OBSERVATION-P4.md`（观察期启动时创建）：日期 / 任务数 / 顺不顺一句话 / 遇到的问题。
- 由日常使用的会话顺手记，不增设仪式感负担；漏记次日补。

## 4. 缺陷分级与重置规则

| 级别 | 定义 | 处置 |
|---|---|---|
| P1 | 任务丢失、结果错误、hub 崩溃、数据损坏、安全越权 | 修复+回归后**重新计时 14 天** |
| P2 | 功能不可用但有绕行、体验明显受损 | 记录并排期修复，**不重置** |
| P3 | 文案/视觉/非核心 | 记录，不重置 |

## 5. 中断与恢复

- 单日未使用：不重置、不顺延（人总有忙的时候）。
- **连续 3 天无使用**：视为观察中断；恢复使用后从当日重新起算 14 天（杜绝「挂机凑 Gate」）。
- 观察期内长假期/出差等可预知中断：提前说明，Gate 日顺延等长天数。

## 6. 观察期冻结面

- P4 特性面**冻结**：只修缺陷（P1/P2），不加新功能。
- P5 的 RFC/设计/原型**可并行**（不动 main 生产代码）；P5 编码合入等 Gate 通过。
- 紧急修复走正常流水线（zcode 写 + codex 审 + 实测）。

## 7. Gate 结论

14 天期满且满足：无未修复 P1 + 任务量达标（第 2 节）→ **P4 Gate 通过**，P5「复杂工作可恢复」（执行事实与接管 + 多步骤断点查看）编码开工。
