# RFC: Jev 决策服务——「派给谁」的 System One 化（P5.1 / StartLux 复活）

> 状态：草案 v1（2026-10-26 凌晨，Hana 起草，待伦哥过目）
> 背景：伦哥反馈①群聊任务需要用户手动指派不合理（应系统指定或 agent 认领）；②拍板用 Jev 决策模型。本 RFC 把 v2 降为实验的 StartLux/DecisionProvider 以 Jev 范式复活。

## 一、Jev 是什么（一段话说清）

TypeSafe AI 2026-09 发布的「系统一模型」：**不生成文本**，输入 state + 类型化问题，一次前向并行输出带校准概率的结构化判定。三原语：**Noul**（是非概率）、**Choice**（≤255 选项选一个+概率分布+置信度）、**Score**（档位打分）。端到端 70-500ms，输入 $0.042/M、输出免费。社区实测中位延迟 76ms、成本降 30 倍；概率校准真实（0.9-1.0 区间判断 98% 正确）。局限：无推理链（要理由的场景弱）、非英语准确率需实测、对措辞敏感、state 上限 32K token。

## 二、为什么适配「派给谁」

- **答案空间天然有限**：候选 = 能力目录里在线且 exposed 的 agent@node，逐单枚举，正是 Choice 原语的形状。
- **高频+要快**：每次派发都问，70-500ms 无感。
- **校准概率治好历史病**：v2 当初把 StartLux 降为实验的根因是「规则降级路径固定 0.5 会被误读为校准概率」——Jev 的概率是 RLCD 校准的，v2 该裁决的前 提变了。
- **CMU 冻结级联**：高置信自动采纳、中置信标记复核、低置信转人工——与 SwarmMind 的人机协同哲学同构。

## 三、架构

```
DecisionProvider（hub 内嵌 decision 包）
  ├─ provider: llm-as-jev（GLM-5.3-Flash 改造提示，首批默认——生态成熟、已有 key）
  ├─ provider: jev-cloud（TypeSafe API，可切换）
  ├─ provider: local-open（StartLux/OpenJev 本地端点，v1.1）
  └─ 输入 state：任务需求（goal/步骤描述压缩）+ 能力目录快照（在线 node、agent、exposed、负载、workdir）
     输出：Choice(建议 target) + 概率分布 + confidence
```

- **一次请求多问题**：同份 state 同时问「派给谁（Choice）/ 是否需要拆分（Noul）/ 复杂度（Score）」——Jev 并行特性免费拿。
- **决策是建议不是必经**：v2「从必经链路移除」原则保留——建议可被人工/Prime 覆盖；差异在建议质量从规则固定值升级为校准概率。
- **置信度三段式**（界面按 v2 口径显示「建议派给 X（本地决策模型）」+来源；校准概率可显示，原禁令针对未校准值，实施时重新裁决）。
- **隐私边界**：云端 provider 的 state 含任务描述明文——local provider 无此虑；provider 配置化由伦哥选。

## 四、联动场景

1. **群聊任务联动**（反馈①主场景）：用户在群说目标 → Prime 读讨论 → 建单/Work 时 target 由 DecisionProvider 建议 → 高置信自动派、低置信群里问一句。用户只说话，不指派。
2. **管理台派单页**：「建议派给 X」一键采纳（最短路径，先做）。
3. **Work 步骤派发**：接管续派时逐步骤给建议。

## 五、分批

| 批 | 内容 | 验收 |
|---|---|---|
| D1 | DecisionProvider 抽象 + llm-as-jev 实现 + 派单页「建议派给 X」 | 中文 state 实测 50 例准确率报告；建议非必经可覆盖 |
| D2 | 群聊联动（消息→建议→派发链路） | 群场景端到端：说目标→自动派对 |
| D3 | local provider（StartLux/OpenJev 择优）+ 冻结级联策略 + 多问题并行 | 本地延迟/准确率对照报告 |

## 六、开放问题（请伦哥裁决）

1. **部署形态**：D1 先用 LLM-as-Jev（GLM-5.3-Flash，已有 key 零新增成本）还是直接上 StartLux 本地部署？「部署在 swarm 中」我理解倾向后者，但 LLM-as-Jev 一天能见效，建议 D1 先跑通、D3 落本地。
2. **置信度显示**：Jev 概率已校准，界面是否解禁百分比显示？（v2 禁令前提已变）
3. **agent 自行认领**（重方案）：是否立为实验区课题，还是先看 Prime 统筹 + Jev 建议的实际体验再说？（我建议后者——先让系统指定跑顺，认领协议复杂度高，别急）
