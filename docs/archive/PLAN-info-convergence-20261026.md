# PLAN：双端 Web 常驻辅助信息收敛方案（2026-10-26）

> 来源：伦哥指示「其他的内容也收纳成站内通知问号这种情况，和 codex 一起整理方案，确定收敛方式」。
> 状态：方案共创完成（Hana 实扫盘点 49 处 + codex 全仓复核逐条表态），待伦哥裁决后立任务实施。
> 起点：2a957d7（站内通知 .help-dot 问号 tooltip，本方案将其升格为体系组件）。

## 一、一句话判据（收敛准入）

**只有隐藏后仍不影响用户理解当前数据、完成操作、判断权限与后果、保存及取得结果的信息，才允许收敛。**

反向清单（永不收敛）：动态数量/预算/时间/产物路径等数据本体、审计结果、救援通道（忘记密码）、操作步骤指引、空态引导、表单 label、页面副标题、错误与凭证展示、追踪号。

## 二、四种处理方式（不是只有 tooltip）

| 形态 | 适用 | 边界 |
|---|---|---|
| **问号短提示**（.help-dot 气泡） | 单一概念口径、无操作的简短解释 | ≤ 两短句，窄屏约 3-4 行；超出改用折叠详情 |
| **原位折叠详情**（details/summary） | 多条件、多分支、路径/API、可复制内容、机制长说明 | summary 用有含义短语（如「断开后的任务处理」），禁用「更多」 |
| **常驻摘要** | 权限、前提、操作后果、期限、结果位置 | 允许一句可见摘要 + 折叠详情搭配；不能因长就全藏 |
| **就地精简** | 该常驻但措辞冗余的提示 | 保留常驻 ≠ 保留原措辞；与收敛正交，可叠加使用 |

### 精简原则（伦哥 10-26 补充：可精简的也不要放过）
1. 能一句说清的不用两句；括号补充说明优先进气泡而非堆在原句
2. 同一口径在页面内多处重复的，只留一处、其余指路
3. 机制解释让位动作语义：先说「做什么/会怎样」，机制原理进折叠或气泡
4. 措辞统一：双端同概念同词（机器/节点、中心端/管理面等既有词典）；删除「注意/提醒/请知悉」类冗余前缀
5. 精简后仍须满足第一节判据：压缩的是措辞，不压信息量——删掉的是冗字，不是限定条件

## 三、组件改造要求（codex 终审意见，.help-dot 现状不宜原样推广）

W3C 悬浮内容合规（可关闭/可移入/持续阅读）+ 触屏可用：
1. 触发器改原生 `button type="button"`（短名称如「通知机制说明」），去掉 tabindex+aria-label 全文方案
2. 气泡改真实 DOM 容器：`role="tooltip"` + 稳定 ID + 触发器 `aria-describedby` 关联（不把全文塞 aria-label 造成读屏重复播报）
3. Escape 关闭且焦点不移动；气泡内禁放链接/按钮等可聚焦控件（那类内容走折叠详情）
4. 触屏：点击显式切换显示（不依赖 tap 碰巧触发 focus-visible），点外关闭；**必须真机实测**，tap 显示目前只是拟定规范
5. 点击区域 ≥24×24px（问号图形可保持 14px，扩大命中区）
6. 气泡视口避让：右边缘、滚动容器裁切（.notify-panel overflow:auto 一类）、窄屏
7. 双端组件契约三层：渲染层 helper 统一结构 + CSS 双端同文字节锁；操作层锚点/交互同构；文案层机制文案单源词典
