## P0 可靠性与诚实性（修订版）

### P0.1 数据新鲜度与并发纪律（原 #1，按审查意见 4 重写）

- **请求序号防旧覆盖**：`S.fetchSeq` 全局递增；每类数据（nodes/tasks/directory）独立 seq，响应返回时 seq 不匹配即丢弃。三类接口**分别保存**（不追求原子快照——各自独立渲染路径，原子性无收益）。
- **响应结构校验**：非 200 或 JSON 结构不符（缺 nodes/tasks 等关键字段）一律不覆盖快照。
- **single-flight**：5s 轮询 tick 时若上轮同类请求在途则跳过本轮（防慢请求重叠堆积）。
- **新鲜度提示**：顶栏独立小字「数据更新于 HH:MM」，由 fetch 成功回调独立更新（不依赖 changed 触发整页重绘）；请求失败保留旧数据+标记「（陈旧）」；覆盖超时（12s 无成功响应即标陈旧）、恢复、首次加载失败（显示明确的加载失败态而非空列表）三场景。
- **在线展示**（纠正原表述）：前端不自行判定在线——展示 hub 返回的 online 字段（服务端心跳超时机制已存在于 internal/hub/session/session.go:312-331）；浏览器自身断网时全局横幅「与中心端失联，显示的是最后已知状态」，不把失联渲染成节点离线。

### P0.2 设置表单保护（原 #2，按审查意见 1 重写）

双路径治理：
- **进页异步重绘路径**（真正根因）：设置页首次渲染时表单区渲染为禁用态（附「加载中」），`loadTokens()` 完成后的重绘**只更新账户信息与令牌列表两个非编辑区**（局部 DOM 更新，不整体 innerHTML 重建设置页）；完成后启用表单。
- **周期轮询路径**：轮询豁免清单加入设置页（与派单表单同权）。
- 验收（进 TESTPLAN-FE）：FE-03 延迟响应测试——拦截响应延迟 3s，先填入修改值→加载完成→值仍在；FE-04 填写中触发轮询 tick→值仍在。两项通过后移除 e2e:231 的 1500ms sleep。

### P0.3 抽屉草稿持久化（原 #3，按审查意见 2 重写）

- **按 task ID 保存草稿**：`S.drafts[taskId] = {note, checked}`（内存 map）；核对表单 input 事件即时写入；抽屉重绘时回填（重绘后 DOM 是新的，值从 S.drafts 恢复）。抽屉关闭不清除（重开同任务草稿仍在），任务终态变更时保留（核对本身发生在终态）。
- 抽屉内**核对表单区**在增量更新时保持 DOM 恒定（只更新状态展示区），双保险。
- 普通弹层与向导的重建问题**不在 P0 处理**，单列为 P2.0 外壳常驻改造。
- 验收：FE-05 填草稿→焦点移出（点页面其他处）→等待轮询 tick→草稿仍在+任务状态已更新；FE-06 关抽屉重开→草稿仍在。

### P0.4 假吊销按钮（原 #4，不变）

「吊销」改「撤下说明」（只读说明弹层）。不动 API。

### P0.5 忙态对象化（原 #5，采纳审查补充）

`S.busy`（Set，存操作对象键如 `cancel:t-xxx`）+ **事件处理器入口双重检查**（不仅靠渲染 disabled——挡住重建窗口期的重复提交）。失败 finally 恢复。

### P0.6 焦点管理与键盘隔离（原 #6，按审查意见 6 补全）

- 弹层/抽屉/向导统一：`aria-modal` 关联标题；打开时焦点移入首个可交互元素；**Tab/Shift+Tab 焦点循环**（Trap：keydown 拦截 Tab，在层内首尾循环）；**背景 inert**（`inert` 属性加到 #app 主容器）；关闭后焦点返回**稳定逻辑目标**（触发元素因全量重绘消失时，返回侧栏对应页签按钮等恒定锚点）。
- 总览可点 metric 从 div 改 `<button>`。
- 验收：FE-07 Tab 循环不逃逸、背景不可聚焦；FE-08 关闭后焦点可见且可操作。
