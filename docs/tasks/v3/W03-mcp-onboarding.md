## REST/MCP与配置应用决定

拟定主人管理面：Node `POST /api/v1/local/mcp/config/preview`、`/apply`、`/revert`；输入配置名、受支持宿主/路径选择、目标地址、授权引用及预期文件版本hash；预览返回脱敏差异与可写性，不含旧密钥。apply先核文件版本和范围，再备份/原子合并，失败原文件保留；revert只撤销本次条目，用户后续修改冲突409，不回滚整文件。它们是人工宿主配置/凭据部署动作，逐端点登记豁免；不经agent工具调用任意文件写入。

Hub生成配置使用前端模板+现有PAT人工操作，不新增任意URL探测或远端文件写接口。可验证程序路径只限同机，外部路径标待调用机核验。复制/下载明文仅来自当前人工授予/临时输入；预览与诊断不得回显保存的token。授权已换发但配置apply失败时分别显示，不能虚报跨文件回滚。

业务验证复用swarmmind_capabilities、nodes/agents与session工具；不另造“验证成功”MCP工具。自动诊断回执通道首版不提供；页面V1–V4可由外部宿主回显供用户确认，并标明用户确认/时间/配置版本，不能渲染成服务器验证。若以后加机器回执，需另列双端REST/MCP/鉴权、防重放RFC，不纳入本包隐性范围。

## 双端形态与六分区

| 分区 | Node | Hub | 统一要求 |
|---|---|---|---|
| ①范围/拓扑 | 本机，默认同机，转发须显式说明 | 中心，默认调用机在外部 | 画清stdio进程→API→执行者，127.0.0.1属调用机 |
| ②调用环境 | 宿主/调用机路径，支持时探测 | 相同字段，远端不探测 | 不拿服务器程序路径代填外部路径，配置同名冲突显式处理 |
| ③人工授权 | W02共享编排凭据 | PAT人工入口 | 管理密钥/模型密钥不入配置，影响范围真实显示 |
| ④预览/应用 | 手动均可，已验证宿主可自动 | 复制/下载，不自动应用 | 已生成/已写入独立状态；失败保留草稿与说明 |
| ⑤V0–V5 | 本机范围 | 中心范围 | 每层未验/通过/失败/用户确认，检查视角与配置版本可见 |
| ⑥维护故障 | 轮换/禁用→重新配置 | PAT撤销/换发→重新配置 | 更改配置重置相关验证，不用旧结果点绿新配置 |

宿主模板至少验证用户实际使用的zcode，Codex模板若未验证标通用手动而非支持；不得把MCP宿主格式不一致硬套JSON。本包不改变模型配置。页面操作使用居中表单modal，诊断明细右抽屉；六区局部更新，换范围先失效旧响应，防止迟到请求把秘密写回已登出页面。
