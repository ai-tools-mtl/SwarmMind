## 1. 服务端最小接线裁定（新端点组与豁免登记）

W03-03 模型的页面消费需要端点暴露。裁定：**不走「经既有 preview 端点携带」**
（preview 是无状态配置预览，验证板是有状态进程内存模型——语义不同源，混载会把
状态写语义塞进只读端点），**用最小新端点组**，全部落在 mcpverify.go 模型之上，
全部 `authLocal`（仅 local_token，prime_token 一律 401）：

| 端点 | 写盘 | 作用（W03-03 模型消费面） |
|---|---|---|
| `GET /api/v1/local/mcp/verify` | 零写盘 | 板面全量快照（六层投影+历史+秘密引用）+ 逐层 not_checked 指引 + 凭据脱敏引用 |
| `POST /api/v1/local/mcp/verify/v0` | 零写盘 | 运行服务端 V0 检查（复用 RunV0Checks，宿主配置安全读）→ RecordV0；文件版本非空即重锚（SetConfigVersion）→ 旧结果如实回落 not_checked |
| `POST /api/v1/local/mcp/verify/v2` | 零写盘 | 服务端视角鉴权探测（DefaultV2Probe(5s) + 当前共享凭据）→ RecordV2；恒标 server_side_view，绝不代证外部 V2 |
| `POST /api/v1/local/mcp/verify/confirm` | 零写盘 | 用户确认登记（RegisterExternalConfirmation；仅 v1/v3/v4/v5，绑定 config_version，疑似明文 note 拒收） |
| `POST /api/v1/local/mcp/verify/config-version` | 零写盘 | 配置版本锚更新（SetConfigVersion）——apply/revert 后由页面以应答 version_after 驱动，相关验证如实回落 not_checked |

**轮换交接面裁定（「轮换后 RotateSecret」零侵入实现）**：轮换动作本体在既有
`POST /api/v1/local/mcp/access/rotate`（mcpaccess.go，禁区不改动）。新接线不挂钩
该端点，改由 **GET 板面时的服务端漂移检测**承担：秘密状态为 user_provided 且当前
共享凭据与「就位观测值」不符（服务端内存全长比对——脱敏引用仅保留前 2 字符，不同
令牌可撞同一脱敏形态，不得以脱敏引用判漂移；观测值仅存内存绝不进应答/日志）→
现场调用 RotateSecret()（凭据相关层 v2/v3/v4/v5 失效留痕，历史保留）并把观测值
推进到当前值（每轮轮换只触发一次）。轮换后用户下一次打开验证板即看到旧结果如实
回落；新凭据重新 apply 后由 V0 检查路径 MarkSecretProvided（脱敏引用+新版本锚）
并同步观测值。模型层 SecretLifecycle 语义零改动，全部经由其公开方法。

**SPEC 六.六同步规则判定**：五端点为本机主人管理面（验证状态/用户确认属主人专属
——agent 无权代用户确认外部验证），同批登记豁免⑮（逐端点依据见 SPEC 原文），
不设 MCP 工具、不补映射表行。

### 1.1 请求/应答契约

- `POST verify/v0` 请求：`{scope, caller_env, host, server_url, mcp_command_path,
  config_name, config_home}`。scope∈node|hub、caller_env∈same_machine|remote 非法
  400；server_url 经 ValidateServiceURL；scope=hub 时 config_home 服务端强制置空
  （宿主配置在调用机上，中心/本机页面都不读）。凭据位服务端自取：node 用当前
  共享凭据脱敏引用、hub 用占位（请求面绝无明文）。
- `POST verify/v2` 请求：`{scope, service_url}`。scope≠node → 400（node 不持有
  中心 PAT，服务端视角探测仅本机凭据可执行）；凭据未生成 → 400。
- `POST verify/confirm` 请求：`{layer, config_version, note?}`。模型层校验失败
  （层非法/source 非 user_confirmed/版本空/疑似明文 note）→ 400 原样透传模型
  错误文案。页面确认对话固定展示当前配置版本锚（用户确认绑定它）。
- `POST verify/config-version` 请求：`{config_version}`；空 → 400。
- 应答形态：`{board:{config_version, layers[], history[], secret},
  credential_masked, credential_env_var, mcp_access_enabled, guidance{<layer>},
  note?}`（GET）；变更端点为 `{check|state, board}`。**任何应答绝不含明文凭据**
  （模型级契约 + 金丝测试锁定）；时间一律 UTC RFC3339。
- guidance：GET 应答携六层 `GuidanceFor(layer, "not_checked")`（「如何检查本层」
  的模型同源文案，页面诊断抽屉直出，前端零二次创作）；v0/v2 应答另携本次结果
  对应细分的指引（v0 逐失败项、v2 按 fail_kind）。

## 2. 六分区与已有端点/模型映射表（node 端 `#/mcp` 子页）

| 分区 | 数据源/动作（全部既有+§1 新端点） | 页面形态 |
|---|---|---|
| ①范围/拓扑 | 页面双选：调用本机（默认）/调用中心；拓扑提示直出 preview `view.notes`（回环陷阱/转发前置） | 卡片 + 选择进 modal |
| ②调用环境 | 表单（modal）：caller_env/host/config_name/config_home/server_url/mcp_command_path；同机路径探测事实来自 preview（view.mcp_path_status）；远端恒标「待外部验证」 | 居中表单 modal |
| ③人工授权 | GET mcp/access（既有授权卡同源）；凭据脱敏引用来自 verify GET；hub 范围如实指路中心控制台 PAT（node 控制台无此入口，不承诺） | 卡片 + 深链 |
| ④预览/应用 | POST mcp/config/preview → diff/writability/conflict/file；POST apply（expected_version+replace_confirmed）→ revert_id；POST revert；模板复制/下载（占位凭据） | 居中表单 modal + 页面结果区 |
| ⑤分层验证 | GET verify 板面；POST verify/v0、/v2（服务端视角恒标注）；/confirm（v1/v3/v4/v5）；诊断明细右抽屉（guidance+历史） | 卡片六行 + 右抽屉 |
| ⑥维护故障 | 轮换/禁用→重新配置说明（指路管家卡/授权卡）；PAT 撤销（hub 范围）；可复制提示词（V4 无副作用/V5 可选执行） | 卡片 |

**点亮纪律（硬规落地）**：V0 自动（v0 端点，服务端视角）；V2 服务端视角探测、
徽标与抽屉恒标「服务端视角」；V1/V3/V4/V5 仅用户确认登记（user_confirmed+时间+
配置版本）；apply/revert/config-version 后相关验证如实回落 not_checked（模型
SetConfigVersion 语义）；自动路径绝不出现「外部已验证」类禁词（mcpverify_test
金丝清单同源，web 新测试同词复验）。

**换范围先失效旧响应**：全部板面写路径（load/v0/v2/confirm/config-version）发送
前自增 `mcpBoardSeq`，应答回来序号不符即丢弃——换范围/换表单后重跑，旧在途应答
不可能点亮页面；modal 内 preview 应答携请求时表单快照指纹，不符即丢弃并提示
「表单已变化，旧预览已丢弃」。

## 4. 复制提示词（全文，双端同文；复制按钮零副作用——不发起任何验证请求）

V4 无副作用查询提示词（PRODUCT-PLAN §12.4 原句）：

> 请通过我配置的 SwarmMind MCP 列出当前目标的机器与 agent，明确它是本机还是中心范围；只查询，不创建任务、不启动模型工作。若工具不可用，报告缺少的工具或错误。

V5 可选执行提示词（默认不运行；注明消耗模型额度；按 §12.4「指定测试 agent+独立
工作区+确认后才提交」形态）：

> 请通过我配置的 SwarmMind MCP 向测试 agent「在此填写能力名」提交一条低影响验证任务：使用独立工作区，只做只读观察并报告结果，不修改项目、不执行发布。注意：执行验证会消耗模型额度——请先向我复述你将提交的内容，等我确认后再提交；完成后按四类结局如实报告：任务被接受 / 执行失败 / 工具权限拒绝 / 工作失败。

## 5. hub 页 V0「页面校验」口径（诚实性定案）

hub 无服务端校验数据源（新端点组为 node authLocal 专属；hub 侧零新端点）。
hub 页 V0 = 纯前端逐项检查（服务地址 scheme/host、路径已填、配置名非空、凭据
占位提示、回环×外部调用机=失败），**区块标题与每项事实恒带「页面校验（非服务端
验证）」限定**；结论徽标用「通过/未通过/警示」但整块注明「本页为前端校验，不构成
服务端验证结论」。配置指纹=前端对生成模板文本的散列（标注「前端配置指纹，非宿主
文件版本 hash」）；任一表单字段变更即重置全部层状态（换配置重置相关验证）。
V2 恒显示「中心端不代证外部授权；PAT 撤销/换发即时失效」；V1/V3/V4/V5 =「等待
外部验证」+ 用户确认登记（本页会话内存）。

## 6. 已知限制（如实登记）

- **preview 应答未携带逐条 issue 文案（W03-02 组装面既有事实，本轮只消费不改动
  mcpcfgfile.go）**：mcpcfgfile.go 的 preview 组装收集了 issues 切片但未附进应答
  payload（文件头注释与实现不一致）；页面 ④ 区据实渲染 file 结构事实（path/
  exists/symlink/writable/version），精确逐项事实指路⑤区 V0 检查（host_file 项
  Detail 携带完整分类文案）。W03-02 面补齐属其文件禁区，移交后续批次裁决。
- node 验证板为进程内存态（模型层契约）：重启后六层状态如实回落 not_checked，
  历史清零；宿主配置文件与撤回登记在盘不受影响。
- 撤回凭据（revert_id）仅保留在页面会话；刷新后须重新预览/应用或手动处理
  （服务端登记仍在，revert_not_found/file_conflict 兜底如实呈现）。
- hub 页用户确认仅存当前页面会话（无中心存储端点）；刷新回落「未验证」并注明，
  绝不伪造持久验证状态。
- V2 探测目标为表单当前 service_url（node 范围、本机凭据）；探测成功只证服务端
  视角，绝不渲染成调用机视角结论（模型 Detail 原话直出）。
- node 页服务地址预填 `http://127.0.0.1:8445` 为默认监听口径（status 端点不暴露
  LocalListen，页面提示以本机实际监听为准修正）。
- E2E（重建 embed 后双端截图、焦点/滚动/键盘/迟到回执）归独立采证轮（任务书
  「验收与证据」节）。
