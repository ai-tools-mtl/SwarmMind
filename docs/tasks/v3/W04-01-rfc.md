## 一、模型定案（internal/collab，无模型外依赖）

新包 `internal/collab`：空间协作内核模型，仅依赖 stdlib + `internal/protocol`（时钟/ID 工具，与 group/sessionx 同口径的叶子包）。Node 本批装配本地实例；Hub（W07）同包接远程 adapter，不重写模型。

### 1.1 空间（Space）

| 字段 | 类型 | 语义 |
|---|---|---|
| `ID` | string | `sp-` 前缀 + 随机 hex。旧群 `g-` ID 独立命名空间，不互认 |
| `Goal` / `Acceptance` | string | 目标 / 可检查验收条件（创建必填 goal；acceptance 可空但 finalize(done) 时策略判据必需） |
| `Mode` | Mode | `manual` \| `builtin` \| `external`——**当前调度方式**，跟随最近一次成功 takeover 的 kind 变化（创建时定初值） |
| `Status` | Status | 九态（§1.2） |
| `Phase` | string | 协作阶段（策略域不透明值：W04 只存不解释；W05-01 赋义） |
| `Members` | []Member | §1.4 |
| `Leader` | Leader | §1.3 |
| `Policy` | Policy | 完成授权 `finish_auth`（默认 `human_only`）+ 领取约束 `claim_principals`（空=任意已授权编排主体可领取）+ `policy_version`（单调递增） |
| `Budget` / `Used` | Budget / BudgetUsed | §1.5 三分离 |
| `Version` | int64 | 空间版本，每次成功变更 +1；写操作携 `expected_version` 防重放/乐观锁 |
| `Archived`/`ArchivedAt` | bool/*time | 归档=列表收纳标记，**不是状态**；只允许终态空间归档 |
| `FinalOutcome`/`FinalReason`/`FinalBy` | string | 定版事实（done/abandoned + 原因 + 定版主体） |
| `PausedReason`/`WaitReason` | string | 暂停原因 / 等待原因（独立展示，产品计划 §11） |

### 1.2 状态转换表（原始值统一，不拼凑现有任务状态）

九态：`pending_config`（待配置）/ `pending_leader`（待管家领取）/ `ready`（可运行）/ `running`（运行）/ `paused`（暂停）/ `blocked`（受阻）/ `needs_review`（待核对）/ `completed`（已完成）/ `abandoned`（已放弃）。后两态为终态。

| 当前态 | 允许转到 | 触发动作 |
|---|---|---|
| pending_config | ready / abandoned | ready（配置完成标记，成员须齐）/ finalize(abandoned) |
| pending_leader | pending_config / abandoned | takeover（合法领取，建立任期）/ finalize(abandoned) |
| ready | running / completed / abandoned | start（显式启动，成员须齐 + 有效负责人）/ finalize |
| running | paused / blocked / needs_review / completed / abandoned | pause / 系统阻断（W04-02）/ finish 经判定 / finalize |
| paused | running / blocked / needs_review / completed / abandoned | resume / finish 经判定 / finalize |
| blocked | running / paused / completed / abandoned | resume（受阻解除后）/ pause / finalize |
| needs_review | running / paused / completed / abandoned | resume / pause / finalize |
| completed / abandoned | （无） | 仅 archive 标记（非状态变更） |

定案要点：
- 转换经**显式函数** `CanTransition(from,to)` 判定，非法转换拒绝（`illegal_transition`，409 语义）；表外路径一律不存在。`ready` 是状态机就绪标记动作（pending_config→ready），与 configure_members 同权限族（主人/当前驱动者），不在任务书逐动作表内因其不涉执行授权。
- `pause` 只允许 running/blocked/needs_review（paused 恒指「运行过的新增派发被阻止」）；pause 只阻止新增派发，在途意图照常收敛落账（N04）；`resume` 不自动恢复被策略/权限阻塞的阻断（blocked 态 resume 需先解除阻断源，本批模型层只认状态机）。
- dispatch 仅运行态受理（先显式启动）；成员未齐/未绑线程各有显式拒绝码（`no_members`/`invalid`）。
- 归档不是第九态之外的态：`Archived` 标记只落终态空间，不删材料、不关原生线程；重复归档幂等（`applied=false`）。
- 创建即态：manual/builtin → `pending_config`；external → `pending_leader`（成员可空，AC14 顺序：领取→配置成员→显式启动）。

### 1.3 负责人（Leader）与任期（term）

```
Leader = { Kind: manual|builtin|external; Principal: 服务端已验证主体名; Term: uint64; LeaseUntil: time }
```

- **term 服务端分配、空间内单调递增、永不复用**（对照 Work：旧 Work 的 prime_term 是调用方自选标签 + 服务端拒绝历史复用；v3 改为服务端分配计数器 `termSeq`，结构性消灭 ABA，不需要 TermsUsed 列表）。
- **初始负责人（创建即定）**：manual → `{manual, 创建者主体名, Term=1}`（创建本身是主人显式动作，manual 无租约）；builtin → `{builtin, "system", Term=1, 租约空}`（选 builtin 即把驱动交给内置服务独立可审计 system 主体；租约空=未授予，system 首次续约即首期授予，成为有效驱动者）；external → 无负责人（Term=0，待领取）。
- **takeover 原子 CAS**：请求携 `expected_term`（读档值，未建立任期=0）；单事务内 `expected_term != space.Leader.Term` → `term_conflict`（同刻两方接管只一成功，N03）。**term 裁决先于版本复核**（expected_term 即接管动作的 fencing token，竞速败者得精确的 term_conflict 而非被 version_conflict 掩盖）。**原请求重放返回旧回执**：同一 `request_id` 命中操作回执表即回放原结果（`dup=true`），不执行、不换 term——重放校验先于一切事务校验。
- **接管语义按 kind 分流**：
  - 主人/system 选 manual/builtin：直接就任（manual 不设租约、principal=就任者；builtin principal 恒为 `system`），调度方式随 kind 切换，授予租约（builtin/external）；
  - 主人/system 选 external：**开放领取**——清空负责人与任期（旧任期随之失效），空间转 `pending_leader`（若原为待配置），由编排主体按领取约束竞取；这是 E14「不自动抢回」的 owner 侧出口（主人显式确认后的重新开放）；
  - 编排主体：**仅可领取**满足全部条件的待领取空间：`Mode==external && Status==pending_leader && Leader.Term==0 && 领取约束允许（claim_principals 空=任意，否则须在列）`；领取固定 external，成功后 pending_leader → pending_config，授予租约。**不能顶替有效任期；租约过期后的接管由人确认**（orchestrate 对过期空间同样拒绝——「不自动抢回」E14；过期满的两方 CAS 接管只在 owner/system 之间成立，N03 以 owner 双方构造）。
- **租约（lease）**：external/builtin 负责人必须持有效租约；manual 负责人不设租约（主人本位）。有效判定：`Term>0 && Principal 非空 && （manual || LeaseUntil 非零 && !now.After(LeaseUntil))`。**边界：`now == LeaseUntil` 视为未过期**（严格过期 `now > LeaseUntil`）。
- **renew**：身份面=同主体 + 同族 class + 当前 term（租约时效不在授权层判）；时效面在动作内裁决——`LeaseUntil` 零值（builtin 创建态未授予）允许**首期授予**，已过期（非零且超时）→ `lease_expired`（409 语义）**不能复活**，只能等 owner 显式接管；续约/授予即 `LeaseUntil = now + TTL`（单次授予上限 24h，租约必须可过期）。manual 负责人续约拒绝（`invalid`：不设租约无需续约）。
- **HTTP 空闲不判死**：过期判定唯一依据服务端单调时钟与持久化 LeaseUntil；MCP/HTTP 调用中断、网页退出、node 进程重启都不改变租约事实（重启后租约按盘上值延续，停机期间跨过 LeaseUntil 的自然过期，不回拨不复活）。

**租约配置默认与测试边界**：

| 项 | 默认 | 说明 |
|---|---|---|
| LeaseTTL | `5m` | Store Options 可覆盖（测试注入 ms 级） |
| 建议续约频率 | TTL/3（默认 100s） | 客户端节奏建议（文档值），连续丢两次续约仍有一次余量 |
| 时钟漂移 | 不设服务端宽限 | 过期判定单钟（服务端）唯一权威，**不引入双钟宽限窗**——宽限即给旧任期续命；漂移由「提前续约」吸收：客户端时钟偏差 ≤ 续约间隔即安全 |
| 重启策略 | 租约随快照持久化 | node 重启不判负责人死、不暂停空间（HTTP 空闲不判死同源）；跨 TTL 的停机导致自然过期，恢复后 owner 显式接管 |
| 测试边界 | fake 时钟注入 | 过期/未过期边界用例钉死 `now==LeaseUntil` 未过期；TTL 边界不接受隐式宽限 |

### 1.4 成员（Member）与线程绑定

```
Member = { Name(agent 名); Role(职责，W05 解释); Workspace(工作区); SessionID(绑定平台会话); BoundAt }
```

- **一成员一原生线程**：成员的 `SessionID` 全局唯一绑定——Store 维护 `sessionOwners: session→space` 映射，同一会话绑定到第二个空间拒绝（`session_bound_elsewhere`）；同空间两成员绑同一会话拒绝（configure 校验）。
- **会话进入空间保存唯一 owner_space 绑定**：绑定动作落 Store 快照，跨重启保持。
- **普通 session_send 绕过空间状态直接推进成员线程的契约，W04-01 固定为方案 A：拒绝并指向 space_dispatch。**
  - 定案理由：方案 B（同一服务入口携 owner/term 校验放行）会在 sessionop 与 collab 之间开出第二条调度通道，双入口即双真相（校验口径漂移、审计主体分裂），违背计划 §5「不能绕过空间负责人另行推进同一自动循环」；方案 A 保持调度单入口（space dispatch），普通插话走空间消息（W04-02 messages 端点），人工深度介入走 pause/接管。
  - 本批交付判定面：`Store.SessionOwnerSpace(sessionID)` 查询 + 错误码 `space_dispatch_required`（人话固定：「该会话已绑定协作空间，请经空间派发推进（space dispatch），普通续轮被拒绝」）。sessionop/service 接线归 W04-02（本批不碰 sessionop，登记 §八）。
- **人工另行工作须暂停/显式交接**：configure_members 改动涉及在途成员（有 pending/accepted 意图）拒绝（`member_in_flight`）；先收束或核对，不靠线程串行锁掩盖逻辑双调度。

### 1.5 预算三分离

| 计数 | 定义字段 | 扣减点 | 与旧 MaxRounds 关系 |
|---|---|---|---|
| `message_count` | `Budget.MaxMessages`（0=不限） | 空间消息落账（RecordMessage，W04-02 接线） | 旧发言预算是它的一员，不直接当执行次数 |
| `dispatch_round` | `Budget.MaxDispatchRounds`（0=不限） | 派发意图受理（RecordDispatch） | **独立旋钮**：一次执行 ≠ 一次发言 |
| 墙钟 | `Budget.MaxWallSeconds`（0=不限） | running 状态累计（进入 running 记锚点，离开 running 结算） | 独立维度 |

- 三计数各自判耗尽、各自拒绝（`budget_exhausted`）；派发前事务内复核（N08）。
- **预算扣减与意图同事务，重放不重复扣**：RecordDispatch 在单快照事务内完成「预算复核→扣减→意图落账→回执登记」；同 `request_id` 重放命中回执原样返回，不二次扣（N02/N05）。
- **配置改预算不自动恢复**：set_budget 只改定义与审计原因，不触碰状态机（暂停中的空间不因充值续跑）。

### 1.6 执行意图（DispatchIntent）——持久对账锚

```
DispatchIntent = { RequestID; SpaceID; Member; SessionID; TurnSeq; TaskID; Term; VersionRef; Status; CreatedAt; UpdatedAt }
Status: pending（已落账未接单）| accepted（执行侧已接单）| converged | cancelled
```

- 至少持久关联 `space_id、member/thread、session_id、turn_seq、task_id、request_id、term、version_ref`——**即使 Task 清理也能对账**（TaskID 恒存意图行，不受任务账本保留期影响）。
- `pending|accepted` = 在途（InFlight）；成员变更/finish/finalize/archive 均有在途护栏（N06）。
- **「先写 Group 再发 Task」幽灵窗口禁止**：意图先于执行持久化（outbox 语义），崩溃后按实物对账；**不能凭回调自动重跑**——本包不注册任何终态回调驱动推进，收敛一律经显式 Converge 调用（W04-02 执行侧接线）。
- 原生输入已送达而结果丢失时只查事实（对账意图 + 原生可查询轮次），无法确定转待核对；不以 CLI 模型回复文本猜「成功」（W04-02 收敛分类执行本句）。

## 二、存储事务边界定案

- **选型：单文件原子快照 `spaces.json`（0600），操作回执表内嵌快照 = journal，pending 意图 = outbox**。不引入数据库依赖（任务书：第一版按操作 ID 的 journal/outbox 实现）。对照纪律：temp（O_EXCL 独占创建）+ fsync + rename + 目录 fsync 尽力而为 + UTC（RFC3339 `Z`，protocol.NowUTC）。
- **加载失败拒绝带病启动**：快照存在但 JSON 损坏 / version 未知 → Open 报错退出（同 W02-01 mcp_access 口径，宁拒启不瞎门）。
- **先写后见**：所有写操作在深拷贝副本上执行 → 副本整体原子落盘 → 成功才替换内存可见态；校验拒绝或落盘失败副本整体丢弃，内存零变更（N05 零虚假接受）。
- **操作 ID 幂等（journal）**：每次写操作携 `request_id`（OpID）；成功回执 `{op_id, kind, 内容指纹, result}` 存入快照内回执表。同 ID 同文 → 原回执原样返回（dup，零执行零扣减）；同 ID 异文 → `request_conflict`。回执表滚动上限（默认 4096 条，超限按 RecordedAt 淘汰最旧）防无界膨胀——**回执保留窗即幂等去重窗口**（对照任务终态保留期先例）：窗口内重放保证幂等；窗口外的极旧重放按新请求处理，创建类操作经**确定性派生空间 ID**（sha256(request_id)）收敛到同一空间，不产生第二个空间；在途意图独立持久，不随回执淘汰。
- **崩溃恢复语义**：落盘成功而应答丢失 → 重启后同 ID 重放命中盘上回执，返回原结果（不重复执行不重复扣）；落盘前崩溃 → 快照停留旧态，操作可重试。**进程恢复不凭回调自动重跑**：Open 不派生任何执行，pending 意图留账供 W04-02 对账（`RecoverIntents` 查询面），回滚失败保留材料聚合报告的收束策略归 W04-02。
- **事务内复核**：授权/状态机/租约/预算/成员/版本全部校验发生在同一 mutate 事务的副本上——决策窗口（调用方预检后）内任何并发变更都会被落盘前重检拦下（N08）。

## 三、逐动作授权表落地（纯判定，主体由调用方传入）

主体（Subject）= `{Name, Class}`，**由服务端鉴权层解析后传入，collab 不读 HTTP、不采信请求自报**。Class：`owner`（Node local_token / Hub 人工管理会话）/ `orchestrate`（PAT、共享编排凭据——**不冒充人工**，对照 W02-01 门先例）/ `system`（内置服务独立可审计主体）。共享凭据只能识别「该授权主体」，不承诺同凭据调用者间隔离。

驱动者（当前 driver）判定：`space.Leader.Principal == subj.Name && class 同族（manual↔owner / builtin↔system / external↔orchestrate）&& subj 携带 term == Leader.Term && 租约有效`。**所有写操作仍有 request_id + expected_version，不因角色跳过状态/版本校验。**

| 动作 | owner | orchestrate（驱动者形态） | system | 前置限制（授权之外的状态校验） |
|---|---|---|---|---|
| pause | ✓ | 仅当前驱动者 | ✓（驱动者） | 非终态；不取消在途、不换 term |
| resume / start / dispatch | manual 模式或持当前任期（完成显式接管） | 仅当前驱动者 | 同 | 状态机允许；start/dispatch 成员未齐拒绝；材料/预算/版本事务内复核 |
| configure_members | ✓ | 仅当前驱动者 | 同 | 仅 pending_config/paused；涉及成员无在途；不修改凭据/完成授权/预算上限 |
| set_budget（/budget） | ✓ | ✗ | ✗ | 记录原因；不自动 resume |
| policy（/policy） | ✓ | ✗ | ✗ | 仅 pending_config/paused 且无在途；策略版本递增 |
| takeover | ✓（CAS 任选 kind） | 仅领取（§1.3 四条件） | ✓（同 owner 形态，owner 语义） | expected_term CAS；term 永不复用 |
| renew | ✗（owner 走接管） | 仅当前驱动者 | 仅当前驱动者 | 同主体/当前 term 且租约未过期 |
| finish（control） | ✗（owner 走 finalize） | 仅当前驱动者 | ✓（明确授权的内置服务，即驱动者形态） | `finish_auth==verified_write_review`（默认 human_only → 403 等人工定版）+ 策略判据通过（§四 hooks）；无在途、同版本 |
| finalize(done/abandoned) | ✓ | ✗ | ✗ | done 须策略判据通过；abandoned 必填原因且无未收束执行 |
| archive | ✓ | ✗ | ✗ | 已完成/已放弃、无在途；幂等标记 |

- 完成授权由主人创建/配置时显式写入并审计；**MCP/REST 的 create/configure 请求若携完成授权字段：接受（主人面本就是授权来源），但 orchestrate 面的同类字段一律拒绝而非信任**（本批 orchestrate 面端点未开线，W04-02/03 接线时按此执行；模型层 `Policy` 只能经 owner 动作变更，结构上封死自授路径）。
- 请求主体与展示标签分开：`Subject.Name` 承担权限，`Leader.Principal` 等自报标签只做归属展示，不承担身份证明（审计原则同 AGENTS.md）。

## 四、策略接口面（W05-01 输入，只定接口不定实现）

```go
// 无副作用验证器接口：实现由 W05-01 供给，collab 在完成判据/阶段推进点回调。
type StrategyHooks interface {
    // EvaluateCompletion 完成判据：验收是否满足（纯判定，不改状态）。
    EvaluateCompletion(space SpaceView) CompletionVerdict
    // ValidateCandidate 候选校验：FINAL 候选/结构化候选合法性（纯判定）。
    ValidateCandidate(space SpaceView, candidate CandidateRecord) error
    // DecidePhaseAdvance 阶段推进判定：返回下一阶段建议（纯判定，是否落账由调用方事务决定）。
    DecidePhaseAdvance(space SpaceView) PhaseDecision
}
```

- `CompletionVerdict = {Satisfied bool; Reason string; EvidenceRefs []string}`；`PhaseDecision = {Advance bool; NextPhase string; Reason string}`。
- **hooks 未装配时完成类动作（finish、finalize done）一律拒绝**（`finish_policy_unavailable`，503 语义）——W04 只开放 finalize→abandoned（主人、必填原因、无在途），不提供「无判据的完成」（任务书：W04 只经主人 finalize 记录 abandoned）。判据不满足 → `completion_not_satisfied`（409 语义），等待人工裁决或材料补齐。
- hooks 经 **Options 装配期一次性注入**（Open 后不可换，规避运行期热替换的判定/落账一致性与数据竞态；W05-01 装配点注入），判定发生在 mutate 事务副本上、与扣账/状态变更同事务提交（N08）。

## 五、旧群兼容映射（不迁移不冒认）

旧 `internal/hub/group`（Group/GroupMessage/主持棒）与 `internal/hub/core`（Work 任期/尝试/collect）记录**原语义保持、原样运行**；v3 空间使用本 RFC 新显式契约。**不做数据迁移；v3 空间不读写 groups.json/Work 账本；旧 API 建的群不出现在空间列表，反之亦然（不冒认）。**

### 5.1 概念对应表

| 旧概念（Group/Work） | v3 空间概念 | 对应判定 |
|---|---|---|
| Group.ID（`g-`） | Space.ID（`sp-`） | 不对应：独立命名空间，互不引用 |
| Group.Goal | Space.Goal | 概念对应，存储与生命周期独立 |
| Group.Status（forming/discussing/concluded） | Space 九态 | **不对应**：v3 原始值独立定义，不拼凑旧任务/群状态 |
| Group.Members []string（纯名字） | Space.Members []Member（职责/工作区/线程绑定） | 概念对应、结构超集：旧群无成员线程绑定 |
| Group.Budget.MaxRounds（agent 发言数） | Budget.MaxMessages / MaxDispatchRounds | **不对应**：发言数预算不映射执行次数（任务书明令） |
| Group 消息 Seq 游标 | 空间消息账本（W04-02） | 游标=读取位置，**不是执行确认**；旧「读游标当推进」在 v3 禁止 |
| HostActive/HostRound/HostTurn（jev 主持棒，终态回调自动接力） | Leader{builtin}+DispatchIntent（显式派发） | 机制**不迁移**：旧回调自动点棒保持旧群原语义运行；v3 空间结果落账不触发任何回调自动重跑，不以旧回调与新负责人双挂（双调度禁止） |
| Group.FinalSeen（FINAL: 前缀候选） | 候选记录（W05 结构化） | `FINAL:` 前缀语义沿用旧群不变；不自动等于 v3 完成判据或交付 |
| Group.TaskRefs（装饰性任务引用） | DispatchIntent.TaskID（持久对账锚） | 概念对应、语义增强：旧引用随群快照；v3 意图承担崩溃对账 |
| Work.PrimeTerm（调用方自选标签 + TermsUsed 拒复用） | Leader.Term（服务端分配 uint64 永不复用） | 语义对应、机制差异：v3 结构性消灭 ABA，不需要复用拒绝清单 |
| Work 接管 CAS expected_term | takeover expected_term CAS | 对应（复用判定形态 + 原请求重放回执先例） |
| Work.Steps/Attempts（计划定死、终态回写、collect 收束） | DispatchIntent + 循环阶段记录（W05-03 扩展） | 部分对应：Work 保持原语义；v3 不重派已完成步骤实现返工（W05-03 追加式关联） |
| Work 终态自动回流下一棒（grouphost 钩子） | 结果落账不再派（暂停语义） | **不迁移**：在途结果留账是事实记录，不驱动下一轮 |

### 5.2 兼容红线

1. 旧 Group/Work API 与数据零改动（本批 `internal/hub/**` 只读参考，未改一行）。
2. v3 空间与旧群在 REST/MCP 面完全分列（`/api/v1/spaces*` vs `/api/v1/groups*`），无隐式互转、无 ID 互认。
3. AC20 回归锚：旧群消息序号/预算/CAS、Work 任期/尝试/collect 的既有测试全绿即兼容性证据（本批未触碰其断言）。
