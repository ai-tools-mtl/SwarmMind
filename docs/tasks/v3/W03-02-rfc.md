## 1. 端点总览与鉴权

三端点全部 `authLocal`（仅 local_token，prime_token 一律 401）——人工宿主配置/凭据部署
动作，SPEC 六.六豁免⑭（同批登记，逐端点依据见 SPEC 原文）：

| 端点 | 写盘 | 作用 |
|---|---|---|
| `POST /api/v1/local/mcp/config/preview` | 零写盘 | 脱敏差异 + 可写性 + 冲突检测 + 文件版本 hash |
| `POST /api/v1/local/mcp/config/apply` | 单条目合并写 | 版本核对 → 备份 → 原子合并 → 撤回登记 |
| `POST /api/v1/local/mcp/config/revert` | 单条目撤回 | 只撤本次 apply 写入的条目 |

三端点只操作**本机**宿主配置（调用环境恒 same_machine——端点写的就是本机文件；外部
调用机属 W03-04/hub 侧复制/下载人工 territory，本端点不涉及）。任务书「禁止远程写调用
者文件」由拓扑自守：写面收敛于请求显式给出的受控 config_home 内的已知宿主布局。

## 2. 请求契约（三端点公共字段）

```json
{
  "scope": "node",                      // node|hub，必填（非法 400）
  "host": "zcode",                      // zcode|codex|其他（未知宿主走通用手动）；apply 仅 zcode
  "config_name": "swarmmind-node",      // 可选；空按 scope 默认命名（DefaultConfigName）
  "config_home": "/abs/path",           // 受控宿主配置根，绝对路径必填（zcode/codex 时）
  "server_url": "http://127.0.0.1:8445",// 必填，ValidateServiceURL 校验
  "mcp_command_path": "/abs/swarmmind-mcp", // 调用机上的 swarmmind-mcp 绝对路径；空=占位
  "credential_ref": "current_prime_token",  // current_prime_token | placeholder
  "expected_version": "<sha256hex>"     // preview 可选；apply 必填；revert 不入参（用登记）
}
```

- **credential_ref 语义（凭据纪律出口）**：请求绝不含明文凭据——
  - `current_prime_token`：写入时取服务端当前持有的共享编排凭据值（s.primeToken()），
    应答/差异只出现其脱敏引用（maskCredential 形态）；明文只在 apply 合并落盘瞬间在
    服务端内存存在，绝不进任何应答/日志/登记回显面。仅 scope=node 合法（hub 目标的
    凭据是 PAT，node 不持有，组合非法 400）。
  - `placeholder`：写入/展示 W03-01 的占位文案（临时输入标记——用户手贴一次性凭据）。
    **apply 拒绝 placeholder**（400）：占位凭据落盘=启动即失败的半无用条目（primewire
    R4「占位配置落盘无用」同口径）；自动写入只支持 current_prime_token，临时输入走
    手动模板粘贴。
- **mcp_command_path**：空=占位符（W03-01 口径）。apply 必须给出且 Lstat 探测存在
  （400 command_missing）——占位 command 落盘无用（primewire R4 同判）；符号链接如实
  注记不拒绝（exec 由内核解析，agentdetect 口径）。preview 一并探测并置
  PathProbedLocally（同机路径探测由端点层传入的 W03-01 交接面）。
- **config_home 绝对路径**：相对路径 400（受控根口径，agentdiscover「宿主配置 home
  绝对路径」同判）。绝不创建宿主目录：.zcode/cli 链不存在 → config_file_missing
  （apply/preview 如实报，绝不 MkdirAll——primewire「宁可手贴不猜布局乱写」同判）。

## 3. preview 契约

**行为**：解析宿主配置（zcode=JSON 真解析；codex=TOML 不解析，见 §7）→ 组装
BuildMcpConfigView（六分区视图，PathProbedLocally 按探测置位）→ 冲突检测
（DetectConfigNameConflict，existing 由端点层从宿主配置解析）→ 脱敏差异 → 文件版本
hash。**零写盘**（含备份、临时文件、目录——单测 grep 断言）。

**应答**：

```json
{
  "view": { …McpConfigView 六分区（凭据位恒脱敏占位）… },
  "file": {
    "path": "<abs>/setting.json",
    "exists": true,
    "version": "<sha256hex>",      // 文件不存在时空串（哨兵值）
    "writable": true,              // O_WRONLY 探测打开（不写内容）成功与否
    "symlink": false,
    "issues": []                   // 人话：非法 JSON/读取失败等（不回文件内容）
  },
  "writability": {
    "can_auto_write": true,        // =GenFormAutoWrite 判定式：node+同机+verified 宿主
    "support_level": "verified_zcode",
    "reasons": [],                 // 不可自动写原因清单（manual_only 等）
    "note": "…"                    // codex 粗检口径/未知宿主如实标注
  },
  "conflict_available": true,      // codex/未知宿主 false（无法解析既有条目）
  "conflict": { …ConfigNameConflict… },
  "diff": {
    "kind": "create | replace",    // 无既有条目=create；有=replace（替换须 apply 显式确认）
    "new_entry": { "command": "…", "env": { "SWARM_NODE_PRIME_TOKEN": "fa********", … } },
    "existing_entry": { "command": "…", "env": { "SWARM_NODE_PRIME_TOKEN": "set" } }
  },
  "version_matches": true,         // 仅请求带 expected_version 时输出；不符=false+note（preview 仍 200 返回新状态）
  "notes": ["…人话…"]
}
```

**脱敏差异口径（任务书：只报结构差异不回显内容）**：
- `new_entry`：将写入条目本体，凭据位=maskCredential 脱敏引用（与 W03-01 同形态）；
- `existing_entry`：既有条目只回 command（路径非秘密）+ env **键名与 set/unset 标记**，
  值一律不回显——宿主配置里的旧密钥（用户自配的任意 token）绝不进应答（零明文金丝
  测试锁定：假密钥预埋宿主配置，preview/revert/apply 应答 grep 不到其完整形态）。

## 4. 文件版本 hash 语义（防 TOCTOU 口径）

- **hash = SHA-256 hex（原始文件字节）**；文件不存在 = 空串哨兵。
- **apply**：`expected_version` 必填（400 expected_version_required）；apply 以安全读
  原语**重读**宿主配置（Lstat 链校验 + O_NONBLOCK 打开 + fd fstat 复核，见 §8），当前
  hash ≠ expected_version → **409 file_changed**（预览后文件已被他人/用户改动，须重新
  preview）。合并、备份、写盘全部基于同一次读取的字节——读后到 rename 之间的极端
  时序残窗如实登记（§8，主人受控面与 agentdetect/primewire 同级口径）。
- **revert**：核对当前 hash 与 apply 登记的 post 版本——相等才撤；等于 apply 前版本
  （apply 实际未落盘的残迹）→ 登记作废 noop；其余（用户后改）→ **409 file_conflict**，
  绝不盲目恢复旧整文件。

## 5. apply 契约

**前置门（顺序即实现顺序）**：
1. 装配门：DataDir 空 → 503（撤回登记无处落）。
2. scope=node 且 host=zcode，否则 **400 manual_only**（GenFormAutoWrite 判定式口径：
   codex=manual_generic_codex 未实测、未知宿主=manual_generic、hub 目标凭据 node 不
   持有——全部指路手动模板，绝不猜布局硬写）。
3. credential_ref=current_prime_token 且当前凭据非空（未生成 → 400）。
4. mcp_command_path 存在探测（400 command_missing）。
5. expected_version 必填；config_home 链安全读（不存在 → 400 config_file_missing；
   符号链接/非普通文件 → 400 unsafe_path；非法 JSON/顶层非对象/尾部多余内容 →
   400 invalid_json）——**原文件字节级保留，绝不硬写**。
6. 写闸门（补充定案，测试驱动收紧）：宿主配置文件自身的写权限位如实尊重——
   O_WRONLY 探测打开失败（只读文件）→ 500 write_failed「不可写（原文件未动）」。
   理由：rename 可绕过文件权限位替换内容，但只读位是主人的保护信号，显式只读的
   在用配置不硬改（与 preview 的 file.writable 同一判定原语，前后口径一致）。
   注意探测语义=文件打开：只读**目录**下文件本体探测仍 true，失败发生在备份
   CreateTemp → 500 write_failed「主文件未动」（同一 fixture 两语义分测锁定）。
6. 冲突门：目标名已存在且 replace_confirmed≠true → **409 name_conflict**（附
   DetectConfigNameConflict 的建议名与处置说明；跨范围撞名同样须显式确认）。

**写入序列（包级互斥锁串行；进程内防并发 apply/revert 交错写）**：
1. 合并：顶层 mcpServers.<名> = 新条目（幂等覆盖同键；其他键**语义级原样**——解码
   UseNumber、重编码 MarshalIndent，与 primewire 同款：其他条目的值不转型不丢数字
   字面量，键序规范化为字母序。任务书「其他条目字节级不动」按语义级解释执行：JSON
   全文重序列化无法保留原始键序/空白，数值字面量经 UseNumber 逐字节保真，测试锁定
   round-trip）；`数值保真`：既有条目非字符串值（端口数字等）原样保留不转型。
2. 撤回登记先行：upsert data_dir/mcp_config_writes.json（0600 原子写，含 post 版本
   hash 与原值快照/删除标记；同文件单槽——新 apply 覆盖旧登记，旧 revert_id 失效）。
   登记失败 → 500 write_failed「宿主配置未动」（保证「apply 成功则 revert 必可用」）。
3. 备份：`<file>.bak-mcpcfg` 整文件备份（0600 原子写，直接覆盖旧备份不堆积——primewire
   `.bak-prime` 同款）。备份失败 → 中止 + 回滚撤回登记 → 500 write_failed「主文件未动」。
4. 原子写：临时文件 + rename，0600（primewire atomicWriteFile0600 纪律同款，本文件
   自持实现，不改 primewire）。写盘失败 → 回滚撤回登记 → 500 write_failed「原文件
   保留」（rename 语义保证原文件在 rename 成功前未被触碰）。

**应答**：`{applied, file, config_name, backup, version_before, version_after,
replaced_existing, revert:{revert_id, config_name, file}, note}`——**不含凭据明文、
不含原值快照**（快照留在服务端登记内）。

## 6. revert 契约

- 入参：`{"revert_id":"…"}`（apply 应答下发）。
- 登记缺失 → 404 revert_not_found；宿主配置文件被删 → 409 file_conflict；只读
  文件写闸门与 apply 同一判定原语 → 500 write_failed（原文件未动）。
- 版本三路（§4）：==post 版本 → 执行撤回（原条目快照回写，或删除标记 → 仅移除本键，
  动其他键零变化）；==pre 版本 → 登记作废 200 `restored:"noop"`（apply 未落盘的残迹
  收敛）；其余 → 409 file_conflict（用户后改，指路手动处理——**绝不回滚整文件**）。
- 撤回执行：备份当前 → 原子写 → 移除登记；登记清理失败 → 200 + 如实 warning
  （撤回已生效，重复 revert 走 noop 收敛，无双重撤回风险）。
- **revert 响应零明文**：恢复的旧条目值不回显（只报 restored:previous_value|deleted）。
- 登记内原值快照含旧凭据：data_dir 0600 域（与 prime_token/mcp_access.json 同域），
  纪律同 primewire 备份「旧凭证残留无害」口径——旧值本就是该文件既有内容，保护域不变。

## 7. 宿主支持矩阵（agentdetect 口径如实）

| 宿主 | 支持级别 | preview | apply | 依据 |
|---|---|---|---|---|
| zcode | verified_zcode | JSON 真解析：差异+冲突+hash+可写性 | 允许（唯一自动写宿主） | primewire 布局事实源实测 |
| codex | manual_generic_codex | 文件存在性/hash/可写性探测；**不解析 TOML**——diff=null、conflict_available=false + note「结构粗检口径（非语法校验），本端不做 TOML 解析（依赖白名单），冲突与差异检测不可用，请按模板手动粘贴」 | 拒绝 400 manual_only | agentdetect 粗检裁决：检测层不做 TOML 语法校验，绝不冒认 |
| 其他/未知 | manual_generic | 不触文件（无已知布局）：file=null，全手动指引 | 拒绝 400 manual_only | 宁可手贴不猜布局乱写 |

## 8. 安全与已知限制（如实登记）

- **路径闸门**（新文件自持，与 agentdetect hostlayout 同纪律）：config_home 先
  filepath.Clean 消尾随分隔符与 "." 组件（根表示统一）→ config_home 本体 Lstat 必须
  真实目录（符号链接 → 400 unsafe_path）→ 中间段（.zcode、.zcode/cli）逐段 Lstat
  真实目录（链接/缺失/非目录 → unsafe_path / config_file_missing）→ 末段 Lstat 非
  链接非异常 → O_NONBLOCK 打开（FIFO 不挂起；Windows 无此语义无需对应物，平台分文件
  同 agentdetect openflags 先例）→ fd fstat 复核普通文件 → 上限读取（1 MiB）并核对
  实得字节数。错误文案不回文件内容（agentdetect 偏移量口径）。
- **TOCTOU 残窗**：逐段 Lstat 之间与 Lstat→Open→rename 的窗口内被同时换型的极端时序
  仍可能读写替换物——O_NONBLOCK+fd fstat 只消 FIFO 挂起面与非普通型误读面。操作目标
  是主人受控 config_home（非不可信面），残窗与 agentdetect/primewire 同级如实登记；
  不可信面等级的逐段 openat 游走属 inputs 包机制，本面不引入。
- **备份含旧凭据**：.bak-mcpcfg 与登记快照同保护域（0600/数据目录），主文件本就含
  宿主配置既有凭据，暴露面不变；介意者可轮换（rotate 即失效旧值）。
- **跨进程并发**：包级互斥只串行本进程；多进程同时写同一宿主配置由版本 hash 门兜底
  （后者 409 file_changed），不引入文件锁。
- **rotate 与已写入配置**：apply 落盘的是当次 prime_token；其后 rotate 自动接线只刷新
  管家影子 home（primewire 链路），本端点写入的其他配置文件持旧值直到主人重新 apply
  ——与手动粘贴流程同限，如实告知（apply 应答 note）。
- **codex TOML**：不引依赖不做语法校验（SPEC 三白名单纪律 + agentdetect 裁决）；
  codex 用户全程手动，本端点只提供文件探测事实与模板。

## 9. 错误码 → HTTP 表

| code | HTTP | 场景 |
|---|---|---|
| unauthorized | 401 | token 缺失/错误（authLocal：prime_token、无 token 均 401） |
| invalid_request | 400 | 请求体非法/字段缺失/枚举非法/服务地址非法/相对路径/credential 组合非法 |
| manual_only | 400 | codex/未知宿主/scope=hub 的 apply；apply 带 placeholder 凭据 |
| command_missing | 400 | mcp_command_path 缺失或探测不存在（不写占位配置） |
| expected_version_required | 400 | apply 未带预期版本 hash |
| config_file_missing | 400 | 宿主配置文件或目录链不存在（绝不创建宿主目录） |
| invalid_json | 400 | 宿主配置非法 JSON/顶层非对象/尾部多余内容（原文件保留） |
| file_unreadable | 400 | 宿主配置打开/读取失败（权限/超限等环境态；预览按事实呈现不报错） |
| unsafe_path | 400 | config_home/中间段/配置文件为符号链接或非普通文件（Lstat 不跟随） |
| name_conflict | 409 | 配置名冲突且未显式 replace_confirmed（附建议名） |
| file_changed | 409 | apply 当前 hash ≠ expected_version（预览后文件已变） |
| file_conflict | 409 | revert 当前 hash ≠ 登记版本（用户后改；引导手动，不回滚整文件） |
| revert_not_found | 404 | revert_id 无登记（含被新 apply 覆盖） |
| write_failed | 500 | 备份/写盘/登记失败、只读文件写闸门（原文件保留，如实报错） |
| internal | 503 | DataDir 未装配（apply/revert 无撤回登记落点） |

## 10. 测试矩阵（fixture 逐条对齐任务书）

## 11. SPEC 六.六豁免登记行（原文）

> ⑭ `POST /api/v1/local/mcp/config/preview|apply|revert`（本机宿主 MCP 配置预览/应用/撤回，W03-02，2026-10-30）：本机主人专属（仅 local_token 可调，authLocal 门，prime_token 一律 401）——人工宿主配置/凭据部署动作：apply 写宿主配置文件=本机资源写入主权面（对照豁免③「写管家影子 home 宿主配置」与④「写 agents 表=执行权」同级先例），暴露给 agent 面即 agent 可自行改写宿主 MCP 接入（凭据部署与调用拓扑自授权），属越权通道；preview/revert 零写盘/单条目撤回（preview 纯只读脱敏差异零写盘、revert 仅撤本次 apply 登记条目且版本不符 409 file_conflict 拒绝），但同属主人宿主配置管理面组（仅 local_token 门禁一致，宿主配置结构事实不对外）；不经 agent 工具调用任意文件写入（写面收敛于受控 config_home 内已知宿主布局单一入口，绝不创建宿主目录、绝不猜布局硬写，codex/未知宿主一律手动），三端点逐条豁免 MCP 映射。
