# W01-03 RFC：Node agent 会话面 + Hub 契约补强 定案

状态：定案（依 W01-01 基准 §3/§5、W01-02 RFC；2026-10-30）。
效力：本文件是 W01-03 实现与测试的定案记录；与任务书冲突以任务书为准并回改本文件。
与 W01-01 基准冲突检查：**无冲突**；本文件全部为基准未覆盖处的补充定案（逐条注明）。

## 0. 不动点

- 主人旧 `/api/v1/local/sessions*` 五端点零变义（不改一行语义；既有 sessions_local_test 零删改全绿）。
- sessionx 内核四原语语义不动；sessionop 既有导出签名不动（本轮只加法：RequestRecord 元数据字段与新原语，见 §2）。
- hub 既有调用（不带新字段）行为零变化——唯一例外是任务书点名的 close 在途拒绝（对一切 close 调用生效，W01-01 基准 §5 已登记为 v3 变更）。
- W01-02 已交付项核对：`runSessionTurn` create 分支的 `AuthorizeWorkspace` 防御位已接线（sessionturn.go，hub 下发轮覆盖）；`CloseSessionLocal` 的 CloseGuard 已接线——本批经 cmd/node 装配 sessionop 后自然生效，无需再改。

## 1. 创建请求 ID（node agent 面 + hub 面）

- **语义**：`request_id` 可选；同键同文返回原会话（HTTP 200 + `dup:true`，body 含原会话），同键异文 409 `request_conflict`；不带 request_id 行为零变化。request_id 命名空间：hub 注册表全局 / node 请求登记全局（调用方保证唯一，跨会话撞键同样 409）。
- **node agent 面**：创建登记入 sessionop 请求登记（`session_requests.json` 持久）——三元组 `(session_id=新分配平台 ID, turn_seq=0, payload_hash=f(agent,cwd,title))`，kind=`session`。**未提供 request_id 时自动生成 `req-<hex>`**（补充定案：任务书「创建请求必须在返回前持久记录平台 ID」要求每次创建都落登记，自动 ID 使 pending 可查闭环不依赖调用方纪律）。f 与轮次指纹同一规范化（trim + UTF-8 清洗 + SHA-256 hex，分部件 `U+0000` 连接）。并发同键同文：ResolveRequest 原子仲裁，败者经 hash 复查一致收敛为重放（补充定案）。
- **hub 面**：store.Session 增 `RequestID`/`PayloadHash`（加法字段，JSON blob 存储零迁移）；创建内容指纹 f(node_id, agent, cwd, permission_mode)。预检 + 事务内重检（同键同文返原会话 dup、异文 `ErrSessionRequestConflict`）。
- **重放不受当前配置状态阻断**：同键命中即查回原会话（内核已发布=内核快照；未发布=pending 投影），agent 能力/工作区校验只拦新创建（补充定案：重放是回执查询）。

## 2. pending 会话查询（首轮发布前可查平台 ID）

- pending 项 = sessionop 请求登记中 kind=`session` 且内核无映射的条目，合成投影视图（字段与内核 protocol.Session 同形：id/agent_name/adapter/cwd/permission_mode/status/turns/turn_count/created_at/updated_at，另加 `pending:true`、`request_id`、`title`）。**status 投影值 `pending`**（补充定案：受理登记事实的投影；会话注册表两值 active/closed 不变，W01-01 §3 口径一致——注册表不加第三态，投影层加值）。
- 受理态由账本事实合成：该会话名下受理轮（Task.Session.SessionID==sid && TurnSeq>0）逐条投影 `{seq, state, error}`（accepted=queued / started=running / finished=终态+记账码）。
- 首轮成功（内核发布映射）后自动并入内核快照、pending 项消失（同一 ID 两者互斥，列表=内核快照 ∪ pending 合并按创建时刻升序）。列表/详情/续轮对 pending 会话全部可用（续轮=以预分配平台 ID 提交 create 轮，经 `CreateWithID` 落内核——平台 ID 从创建起稳定）。
- RequestRecord 加法字段（旧文件缺省零值兼容，加载零迁移）：`kind/agent/cwd/title/task_id/trace_id`。新原语：`ResolveRequestWith`（带元数据登记）、`SessionCreation(sessionID)`、`SessionCreations()`（pending 投影源）。`ResolveRequest` 签名与行为零变化。

## 3. 轮次 request_id（node agent 面 + hub 面）

- 同键同文查回原回执（200 + `dup:true` + 原 turn 引用）、同键异文 409 `request_conflict`；指纹=完整规范化 prompt（与 hub PromptHash 同一规范化）。
- node：受理互斥段内先查登记（命中即回放/冲突，先于序号推导——并发同键重放收敛为回放而非冲突，补充定案）；新受理在 AcceptOrigin 之后登记（落盘失败如实报错：轮已受理、登记未生效，重试将分配新序号——N07「盘为真相」纪律，已知限制）。回执重放源=登记元数据 task_id/trace_id（不依赖账本保留窗口）。
- hub：store.SessionTurn 增 `RequestID`（加法）；预检 + 事务内重检；重放回执与 turn_seq 重放同型（行留痕权威）。
- **显式 turn_seq（node agent 面）**：仅支持重放——已知受理序号同文回原回执、异文 409 `turn_seq_conflict`；未知序号（跳号）409 `turn_seq_conflict`（node 面不收跳号，与 hub 同判；补充定案：node 序号由受理推导，跳号受理会破坏高水位连续语义）。

## 4. 队列上限（hub）

- 上限 16，单一真相 `protocol.SessionQueueLimit`（sessionop.DefaultQueueLimit 改为引用同值，消除双常量漂移——补充定案）。
- `SubmitTurn` 对**新受理** send 轮：非终态轮行计数 ≥16 → `ErrSessionQueueFull` → 409 `turn_queue_full`；预检 + 事务内双检（同 first-turn-exclusive 模式）；重放/幂等回执不受限（先于队列判定）。首轮独占逻辑不变（其存在即蕴含 create 期上限）。

## 5. close 在途拒绝（hub + node）

- hub `CloseSession`：存在非终态轮行 → `ErrSessionCloseInFlight` → 409 `close_in_flight`（指向取消/等待）；预检 + 事务内重检；已 closed 幂等 dup 保留（先于在途判定）。**对一切 close 调用生效**（任务书点名的行为变更，W01-01 基准 §5 登记）。
- node 主人 close：CloseSessionLocal 的 CloseGuard（W01-02 已交付）经本批 cmd/node 装配生效，语义同上。

## 6. 取消端点（人工专属；agent 面不含 cancel/close）

### 6.1 node 面 `POST /api/v1/sessions/{id}/turns/{seq}/cancel`（authLocal）

直调 `sessionop.CancelTurn` 同步出回执：200 `{"cancel":{session_id,turn_seq,task_id,outcome,status,error}}`（outcome=queued/executed/unknown 如实）；`turn_already_finished` 409 / `turn_not_found` 404 / `cancel_unconfirmed` 500（不虚报）。等待预算：CancelTurn ConfirmBudget + 调用侧 30s ctx 上限。

### 6.2 hub 面 `POST /api/v1/sessions/{id}/turns/{seq}/cancel`（s.auth：cookie/PAT）

按目标轮任务现态三路（补充定案，取代「一律投递取消任务」的单路形态——未投递轮在 node 无受理记录，取消任务必得 turn_not_found，直接本地撤回才满足「排队取消确定性」）：

1. **终态轮行**：Error 为取消类记账码（turn_cancelled_queued/turn_cancelled_executed/turn_cancel_outcome_unknown）→ 200 幂等回执（重放）；其余 → 409 `turn_already_finished`。
2. **目标任务 submitted（未投递）**：本地 `CancelTask`（信箱撤回，确定性不 spawn）→ 200 回执 `{outcome:"queued", error:"turn_cancelled_queued"}`；随后把轮行 Error 由通用回写的 `cancelled` 细化为 `turn_cancelled_queued`（同事件内的记账细化，仅当行非终态 Error==cancelled 任务==cancelled 才改写——排队取消在 hub 侧确定性成立）。已知竞态：ack 超时回退形态下任务可能实际已在 node 手中，此时回执记 queued 而实际为执行取消——node 的分类结果随任务结果留档可对账，轮行以先到为准。
3. **offered/acknowledged/running**：投递**取消任务**（协议加法：`SessionTurnRef.Op=SessionTurnOpCancel` + `CancelTurnSeq` 字段；任务不占轮次号 TurnSeq=0，幂等键 `scancel:<sid>:<seq>`）→ 202 `{"cancel":{...,cancel_task_id,trace_id}}`；node 侧接 `sessionop.CancelTurn` 执行（证据分类），取消任务结果与目标轮任务结果都沿任务结果链回写轮行（先到保留，两路记账码一致）。
   - node 执行调度：取消任务**旁路 workdir 互斥与并发信号量**（补充定案：被取消轮正持 cwd 锁与并发槽，取消任务若排队等锁/槽则「取消等被取消者自然结束」自引用死锁——取消任务是管理动作非执行负载，仅触发信号+等待收敛，不占执行资源）。
   - 取消任务结果回执分类落轮行：queued/executed/unknown 三码写入；`turn_already_finished`/`turn_not_found`/`cancel_unconfirmed` **不写轮行**（行由目标轮自身结果或后续状态收敛，防未确认回执抢先落终态虚报）。
   - **turn_not_found 兜底**：node 无该轮受理记录（取消任务先于投递到达的窄窗口）→ hub 对目标任务补发 `CancelTask` + submitted 态细化 queued（兜底闭合「取消先于受理」窗口）。

### 6.3 cancelled 投影落点（W01-01 §3 落地）

- hub `projectTurn`：终态行 Error 前缀为取消类记账码 → 投影值 **`cancelled`**（store 增 `TurnStatusCancelled` 常量，旧六态不改名不删）；`turn_cancel_outcome_unknown` → failed（待核对，绝不记成功）。node 侧账本终态由 W01-02 已交付（cancelled/failed + 三码），本批经 hub 轮行回写贯通。
- hub 不 import node 包：记账码以 hub core 字面常量对齐，测试锁双端同值。

## 8. cmd/node 装配（W01-02 遗留项闭环）

- `node.yaml` 增 `session_workspace_roots: []string`（空缺省=放行保持现状）；`run()` 装配 `sessionop.New(dataDir, led, Options{AllowedWorkspaceRoots, Log})` 注入 `service.Config.SessionOps`——队列上限/取消记账/CloseGuard/重启收敛/工作区授权全链生效。
- 会话取消等待预算：node cancel 端点 ctx 30s；取消任务执行 ctx 30s（ConfirmBudget 2s 之上的人机可感上限）。

## 9. 已知限制（如实）

1. hub submitted 撤回路的 queued 回执存在 ack-超时回退竞态误标窗口（§6.2 路径 2；node 分类结果留档可对账）。
2. node 轮 request_id 登记在 AcceptOrigin 之后：落盘失败时轮已受理而登记未生效，重试分配新序号（N07 纪律，不虚报）。
3. pending 投影的 title 仅受理登记期可见；内核发布后 protocol.Session 无 title 字段（内核注册表不动）。
4. cancel 任务与目标轮结果的到达次序不保证，轮行以先到为准（两路记账码一致，收敛值确定）。
5. W01-04 交接：node 会话四工具（create/send/list/status）投影本批 REST；本批不装 cmd/swarmmind-mcp。
