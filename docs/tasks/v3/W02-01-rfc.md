# W02-01 RFC：持久授权开关、共享编排凭据与管家角色解耦

状态：定案（随 W02-01 实施批次落地）。上游：`docs/tasks/v3/W02-mcp-access.md`、基准 `docs/tasks/v3/W01-01-baseline.md` §1/§5。
核心裁决：**调用权与管家角色解耦**——主人可不选管家就启用外部调用；默认禁用；显式 enabled 是唯一启用态；「选择管家」不再暗中换发全体调用者共享的密钥。

---

## 一、新状态文件格式

路径 `data_dir/mcp_access.json`，权限 0600，原子写（独占临时文件 + fsync + rename，复用 primewire 的 `atomicWriteFile0600`），时间一律 UTC（RFC3339，`Z` 后缀）。

```json
{
  "version": 1,
  "enabled": false,
  "updated_at": "2026-10-30T08:00:00Z",
  "source": "migration"
}
```

| 字段 | 类型 | 语义 |
|---|---|---|
| `version` | int | 格式版本，恒 1；读到未知版本按错误处理（拒绝猜测意图，宁拒启不瞎门） |
| `enabled` | bool | 编排授权开关。**显式 enabled 是唯一启用态**；文件不存在≠启用 |
| `updated_at` | string | 最近一次状态落盘时刻（UTC） |
| `source` | string | `"migration"`（启动迁移推导）\|`"owner"`（主人经 PUT 显式变更）——服务端鉴权层已保证写方必为 local_token（authLocal 门），主体不采信请求自报 |

失败语义：
- **加载失败**（文件存在但 JSON 损坏 / version 未知）：启动报错退出（授权状态不允许带病猜测；人话指路检查或删除该文件后重启重新迁移）。
- **保存失败**（盘满/权限/目录只读等）：如实返回错误（HTTP 500），内存态保留旧值、盘上旧文件原样——**不虚报成功**。内存态与盘上态可能短暂分叉，重启以盘为准；错误文案注明「旧状态已保留」。

## 二、迁移判定表（旧配置 → 新状态）

启动时（cmd/node 装配点）`mcp_access.json` 不存在才推导一次；**落盘后显式状态即唯一真相**，重启/管家增删不再重推导。迁移判定时点**先于** prime_token 自动生成（保证「只有启动自动生成的 token 文件不能视为授权」——判定那一刻自动生成尚未发生）。

| # | 盘上前提（迁移判定时点） | 迁移结果 | 字段级依据 |
|---|---|---|---|
| M1 | `mcp_access.json` 已存在 | 原样加载，**不重推导** | 显式状态唯一真相；改 node.yaml prime_agent 后重启状态不变 |
| M2 | 无状态文件 + node.yaml `prime_agent` 非空 + `prime_token` 文件存在且可读（len≥32，与 ensureTokenFile 复用判定同口径） | `enabled=true, source=migration` | 任务书：仅旧 prime_agent 非空**且既有有效 prime_token** 的配置可认定已授权（旧契约=声明+凭据双在位） |
| M3 | 无状态文件 + `prime_agent` 为空（token 文件在与不在均同） | `enabled=false, source=migration` | 任务书：只有启动自动生成的 token 文件不能视为授权；未声明管家=未授权 |
| M4 | 无状态文件 + `prime_agent` 非空 + `prime_token` 文件缺失/不可读/过短（<32 字节） | `enabled=false, source=migration` | 凭据不在位不能认定已授权；保守缺省禁用（宁禁勿放），主人可一键显式启用 |
| M5 | 全新实例（无 node.yaml / setup 态，`prime_agent` 空） | `enabled=false, source=migration` | 新实例默认禁用；向导落盘重启后状态文件已在（M1），不随管家选择翻起 |

迁移结果在启动日志注明（推导结论 + 依据 + 落盘路径）。迁移写盘失败：启动报错退出（授权状态必须显式落盘，不允许仅内存推导值跑起来——盘是唯一真相）。

## 三、端点设计

全部仅 local_token 可调（authLocal 门，主人管理面；prime_token 调用 401）。响应统一 `Cache-Control: no-store`。三个端点均为凭据授予/本机主人管理面，属 SPEC 六.六人工专属豁免类（豁免登记见 §七冲突清单）。

### 3.1 `GET /api/v1/local/mcp/access`

```json
{
  "enabled": false,
  "credential_masked": "ab********",
  "scope": "启用后，持共享编排凭据（prime_token）的外部 MCP 调用方可向本机派发任务；禁用期间这些调用被拒绝（403 mcp_disabled），主人本机管理（local_token）不受影响。禁用不等于撤销凭据——作废旧凭据请使用「轮换」。",
  "prime_agent": "echo",
  "updated_at": "2026-10-30T08:00:00Z"
}
```

- `credential_masked` 脱敏规则：取当前共享凭据前 2 字符 + `"********"`（生产为 64 位 hex，如 `ab********`）；凭据为空 → `"未生成"`；长度≤4 的异常短值 → `"sw****"`。**任何响应绝不含明文凭据**。
- `prime_agent` 为当前管家名（可空，仅展示）。

### 3.2 `PUT /api/v1/local/mcp/access`

请求体 `{"enabled": bool}`（缺字段/非法 JSON/非 bool → 400 `invalid_request`）。持久化成功 → 返回同 GET 形态；持久化失败 → 500（错误体如实说明，**不返回成功形态**，内存与盘上均保留旧态）。PUT 保存开关**不返回任何密钥**（任务书权限矩阵明文要求）。

### 3.3 `POST /api/v1/local/mcp/access/rotate`（新）与 `POST /api/v1/local/prime/rotate`（旧别名，保留）

**同一实现**（收敛既有 prime rotate 逻辑）：重生成 → 原子写盘（data_dir/prime_token，0600）→ 同锁（muPrime）内存重载（旧值即失效）→ 自动接线刷新管家影子 home 内 SWARM_NODE_PRIME_TOKEN。**一次返回新明文**、No-store、绝不入日志。失败（生成/写盘）→ 500「旧凭证仍有效，可重试」，不报成功。

响应（旧字段全保留 + 新增 `enabled`）：

```json
{
  "prime_token": "<新明文，仅此一次>",
  "prime_agent": "echo",
  "mcp_config": { "command": "...", "env": { "SWARM_TARGET": "node", "SWARM_NODE_URL": "...", "SWARM_NODE_PRIME_TOKEN": "<新明文>" } },
  "wired": true,
  "wired_target": "/path/setting.json",
  "enabled": true,
  "note": "..."
}
```

## 四、authOrchestrate 新门语义与错误码表

### 4.1 判定表

先认证（401）后鉴权（403），拒绝理由优先级：setup 态 > 授权未启用。

| 主体（认证后） | setup 模式 | standalone/networked + enabled | standalone/networked + disabled |
|---|---|---|---|
| local_token（主人） | 403 `prime_required`（setup 文案不变） | **放行**（恒放行：无需 enabled、无需管家） | **放行**（恒放行） |
| prime_token（共享编排凭据） | 403 `prime_required`（同上） | 放行 | 403 `mcp_disabled` |
| 无/错凭证 | 401 | 401 | 401 |

- **local_token 恒放行**：主人派单天然合法（2026-10-22 裁决延续并升格），调用权不再依赖 prime_agent 与开关。
- **prime_token 需显式 enabled**：唯一门条件。prime_agent 是否声明与门无关（解耦核心）。
- 退役分支：「尚未钦定统筹」「统筹凭证未配置」两条 prime_required 拒绝随解耦删除（prime_agent/凭证在位性不再是门条件；凭证为空时任何 token 都无法认证为 prime 级，该分支对 prime 本不可达）。

`mcp_disabled` 人话文案（指路主人控制台）：
「编排授权未启用：请由本机主人在控制台启用 MCP 编排授权后重试（调用权与管家角色已解耦，启用无需钦定管家；本机主人 local_token 派单不受影响）」

### 4.2 错误码兼容表（旧客户端视角）

| 场景（旧） | 旧响应 | 新响应 | 兼容影响 |
|---|---|---|---|
| setup 模式编排 | 403 `prime_required` | **不变**（码与文案逐字节保留） | 无 |
| prime_token + 旧已授权配置（prime_agent 非空+token 在位，经 M2 迁移 enabled） | 202 | 202（能力范围不变，不额外开放主人/local 端点） | 无 |
| prime_token + 从未配置/未钦定（旧 403 `prime_required`「尚未钦定统筹」） | 403 `prime_required` | 403 `mcp_disabled`（人话指路） | 码变更。旧 swarmmind-mcp 客户端对 `prime_required` 的特判提示不再触发，走通用错误路径——服务端 message 原话透传仍可见（cmd/swarmmind-mcp nodeAPIErr 通用分支），指路人话由服务端承担；客户端特判文案改造属 W02-02 |
| prime_token + 迁移为 disabled（M3/M4：未声明管家或凭据缺失） | 403 `prime_required` | 403 `mcp_disabled` | 同上；能力不回退（旧契约下这些场景本就 403 拒绝） |
| local_token 编排 | 202（需 prime_agent 非空，否则 403） | 202（恒放行） | 仅放宽：旧 prime_agent 为空时 local 从 403 变 202（解耦目标行为） |
| 只读面（authRead：目录/状态/任务/产物） | local\|prime 双收 | **不变**（disabled 不拦只读——门只管编排） | 无 |

`prime_required` 错误码**不消失**：保留于 setup 分支；`mcp_disabled` 为新增码，仅出现在「prime_token + 未启用」场景。

## 五、declare 去（credential）换发与响应字段兼容表

`POST /api/v1/local/prime/declare` 语义变更：**只做管家声明**——校验 agent 存在 → yaml round-trip 写 node.yaml `prime_agent` → 即时生效 → 卡片 Orchestrator 声明联动。不再调用轮换、不改写 prime_token（内存与盘上均不动）、**不自动改写调用权状态**（mcp_access.json 不被 declare 触碰）。

保留的行为：**钦定即接线**（primewire）仍执行——把*当前*共享凭据合并写入新管家影子 home 宿主配置（写盘≠展示；这是管家获得凭据载体的既有机制，且 disabled 时该凭据过不了门、处于休眠）。当前凭据为空（内存无凭证，仅测试构造可出现）→ 接线降级。

失败语义简化：declare 不再有凭证副作用——任一步失败（node.yaml 读/写/解析）一切保持旧态，重试即收敛；旧文案中「凭证已轮换（旧凭证失效、新凭证未展示）」的残局说明整段退役。

响应字段兼容表：

| 字段 | 旧 | 新 | 兼容策略 |
|---|---|---|---|
| `prime_agent` | 钦定名 | 不变 | 无 |
| `prime_token` | 新换发明文 | **保留字段，恒 `""`**（语义注记：不再随钦定换发/展示；凭据一次性展示只发生在启用/轮换事件） | 字段在场，旧解析不炸；值不再有明文。旧「换管家即踢旧凭据」运维习惯失效——撤销改由显式「轮换」承担（本任务的目标行为变更，非回归） |
| `mcp_config` | 含新明文 token 的连接片段 | 保留结构；`env.SWARM_NODE_PRIME_TOKEN` 为**脱敏引用**（同 §3.1 规则） | 字段在场；片段不再可直接粘贴使用——真凭据在已接线的宿主配置内，或经「轮换」获取一次性新凭据 |
| `wired` / `wired_target` | 接线口径 | 保留（语义不变：仍以当前凭据自动接线） | 无 |
| `orchestrator` / `orchestrator_error` / `hub_synced` | 声明联动三态 | 不变 | 无 |
| `note` | 含「旧凭证已随本次钦定失效」 | 文案更新：「钦定不再换发共享凭据（调用权与管家角色解耦），既有凭据与授权状态不变」+ 接线口径 | 文案级 |

## 六、prime_token 文件与测试改写口径

- `prime_token` 文件自动生成**保留**（兼容：既有部署路径、M2 迁移依据、轮换写盘目标），但其编排可用性由 enabled 门控；文件本身不再是授权证据。
- AC20 既有测试（prime_test/primewire_test/server_test/exposed_e2e）权限断言**按新规则改写而非删除**，逐条改动理由随测试注释与本 RFC §八登记；新增 mcpaccess_test.go 覆盖授权矩阵/轮换/迁移表/declare 回归/原子性。

## 七、冲突与越界登记（不绕行，上报裁决）

1. **SPEC 回写越界**：本包禁区未含 SPEC.md——六.六豁免清单需显式登记新端点组（`/api/v1/local/mcp/access*`：凭据授予+本机主人管理面豁免，理由同③④⑧口径）、鉴权段（authOrchestrate 判定表 §四）与「统筹凭证」段的去换发口径，须由 SPEC 归属批次回写；本 RFC 为其唯一输入。
2. **node 控制台（internal/node/web）越界**：钦定完成页仍渲染 `prime_token`（将显示空）与 `mcp_config`（掩码引用）、「换一个管家」确认话术含「钦定即换凭证，旧凭证立即失效」（已不成立）；P07 授权区（启用/禁用/轮换 UI）本就属 W03-04。web 改造随其归属批次走，本批不动。
3. **cmd/swarmmind-mcp 越界**：`prime_required` 特判提示（「接入即总理」故障入口）与 status 页「未钦定（submit 将 403 prime_required）」文案需随 W02-02 改造（任务书 W02-02 明确归属）；本批服务端 message 透传保证旧客户端不失语。
4. **docs/OPERATIONS.md** 故障表「submit 返回 prime_required → 声明 prime_agent」条目需随 SPEC 批次更新为 mcp_disabled 新口径。

## 九、已知限制

- 禁用不清除已接线宿主配置内的凭据（与「撤销统筹不清理」同口径）：禁用=门控拒绝，凭据作废=显式轮换；两者独立（任务书：MCP 授权/管家/空间任期三者独立）。
- 状态文件仅记录 enabled 单开关；不显示逐客户端撤销、不做按 agent 资源级权限（任务书明确不建设）。
- 首版无 P07 页面（W03-04）；本批交付端点+迁移+门语义，控制台消费后置。
