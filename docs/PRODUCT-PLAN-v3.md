# SwarmMind 产品方案 v3

> 2026-10-29。基于用户确认的使用形态，由 Codex 与本机 zcode 原生会话讨论整理。本轮第10–17节补齐页面、流程、异常、MCP接入与任务拆分；讨论收敛状态及记录见文末。本文是目标方案，不表示所有能力已实现；现行协议与运行行为以 SPEC 和对应版本测试为准。

## 1. 产品定位

**SwarmMind 是本机可独立使用、联网后可跨机器协作的 agent 工作台。** 它连接已经配置好的原生 agent，保持各自模型、工具与工作区，在可持续会话中完成单 agent 工作和围绕目标的多 agent 协作。

三条产品主线：本机独立工作；通过中心连接多台客户端；围绕目标选择参与者并持续协作。任务、账本、产物、通知和恢复机制服务于这三条主线。

## 2. 部署与调用形态

| 组成 | 职责 | 运行依赖 |
|---|---|---|
| 客户端 Node | 发现并登记本机 agent、执行原生会话、提供本机协作与管理、开放本机 MCP | 本机独立运行，无需 Hub；执行能力依赖相应 agent 及配置 |
| 中心端 Hub | 汇集开放能力、管理跨机协作、路由执行与回传结果、提供网页和全网 MCP | 不要求本机安装 agent 或智行管家；执行委派到客户端 |
| 外部 agent / 智行管家 | 经 MCP 调用本机或全网能力，理解需求并组织协作 | 可运行在任何获授权且能连接相应入口的机器上；属于可选调用者 |
| jev 决策服务 | 根据目标、阶段与候选返回执行者/参与者选择 | 可选模型接口；服务可部署本机或远端，不要求安装完整 agent |
| 网页 / 未来桌面端 | 表达目标、继续会话、管理配置、查看执行、处理异常 | 调用同一服务接口；桌面端不另建业务状态机 |

中心端没有外部 agent 时仍能由用户通过网页使用。协作调度内核是无模型的确定性程序，动作集封闭；它以明确的流程状态机推进任务，需要语义分配时调用配置的 jev。jev 输出只是待校验的决策数据，不直接执行任意指令。无 jev、无管家时仍支持手选执行者和明确的规则流程；不承诺自主理解和拆解任意复杂需求。没有可用执行节点时可以管理配置和记录，但不能实际完成 agent 工作。

MCP 是能力出口：给外部 agent 配本机 MCP 就调用本机能力，配中心 MCP 就调用全网能力。stdio MCP 可由外部机器上的适配进程启动并访问目标 API；不意味着公网直接开放 stdio 或必须在 Hub 安装 agent。

## 3. 用户只需理解三个主要入口

| 入口 | 用户要做的事 | 详情内提供 |
|---|---|---|
| 会话 | 找一个 agent 直接工作、继续历史线程 | 原生绑定、轮次、执行记录、文件、等待与权限状态 |
| 协作空间（群聊） | 给出目标，组织多个 agent 讨论、编写、审查与返工 | 参与者、调度方式、当前阶段、问题、版本、产物和交付结果 |
| 资源 | 管理 agent、连接与配置 | 本机发现、远端机器、开放范围、MCP、管家与 jev 配置 |

Task 和 Work 保留技术标识及高级查询入口，日常界面不要求用户先理解它们。设置和诊断作为辅助页面，不增加新的主要工作入口。

## 4. 会话与协作空间

每个会话绑定确定的 node、agent 配置、工作区与原生 ID，不能恢复“最近一条”。新输入是该会话的新轮次；同一线程单写者，不同线程遵守节点配额与工作区互斥。TUI 和平台同时写同一原生线程暂不承诺自动互斥，应明确占用或交接。

协作空间拥有目标、验收条件、参与者、会话绑定、阶段、路由负责人、消息记录及结果。默认每个目标的每个成员拥有独立原生线程；一个 agent 在不同目标中使用不同线程。需要多个子任务时可显式新增成员工作线程，不按消息无限建线程。

共享消息不等于唤醒全员。一次显式路由明确记录收件成员、输入范围、原生会话、幂等键和对应执行。被唤醒成员收到相关新增内容和当前任务；游标只记录读取位置，不触发唤醒，投递/执行确认另行记账。恢复历史或重复投递不能再次触发执行。

会话历史由原生 agent 管理，平台保存路由和协作事实。短期群消息窗口不能承担长期恢复；活跃空间保留目标、决定、未解决事项、成员绑定、当前版本和必要消息/材料，直到用户归档或按明确策略处理。清理执行日志不得破坏活跃会话的恢复引用。

## 5. 调度方式与独立运行

每个协作空间选择一种调度方式：

| 方式 | 谁决定下一步 | 平台负责什么 |
|---|---|---|
| 手动 | 用户指定执行者与任务 | 可靠执行、会话续接、结果记录 |
| 内置协作 | 明确流程规则；需语义选择时由 jev 返回结构化选择 | 校验候选、推进阶段、绑定会话、处理等待与停止 |
| 外部管家 | 外部 agent 通过 MCP 给出计划和派发动作 | 校验权限/版本/任期，执行并记录，不并行另作自动决定 |

jev 负责选择，不承担隐藏的长期代理角色；管家可以调用 jev 辅助选择。选参与者与选下一步执行者是两个动作；成员加入后不随每条消息反复改组。服务端校验被选者存在、已开放/获授权、符合当前空间范围及预算。决策失败或选择不合法时明确等待、允许手选，不静默改用别的模型或扩大参与范围。

同一空间同一时刻只有一个有效调度负责人，切换显式接管并使旧任期失效。外部调用者可查询、发消息或在权限允许时发起直接工作；不能绕过空间负责人另行推进同一自动循环。人为插话、暂停与取消通过统一控制入口记录。

外部管家可提出开放的计划与验收建议，但涉及执行的动作统一通过服务端的权限、任期、幂等和版本检查并落账后生效。审计主体由服务端鉴权解析，与请求自报身份分开保存。拥有管家角色不自动获得凭据管理或权限审批能力。管家断线默认暂停新增协调、继续接收在途结果，不自动改由另一调度者推进；恢复先读账本。结果落账不自动恢复已暂停的下一步。

断线检测采用明确的调度租约/续约与暂停规则，不能将一次MCP调用结束或普通HTTP空闲当作管家离线。超时值、续约频率、CAS任期与过期请求拒绝机制由实施RFC定义并测试；首版只提供显式接管。后续若提供自动接管，须显式预授权并完成旧任期失效验证。

内置流程首批只提供直接委派、有限轮次的讨论与“编写—审查—返工”，不建设通用工作流平台。开放式需求拆解交给外部管家或由用户确认计划。

## 6. 群讨论与编写审查

统一底层为“选择执行者 → 继续绑定会话 → 等待结果 → 记录决定 → 选择下一步”，采用一个协作内核和两个独立完成策略，不将群讨论强塞进固定的开发流程：

- 讨论：jev/管家选择下一位或明确并行的一组成员，交换观点，形成候选结论；达到停止条件后交付或等待用户决定。
- 编写审查：编写线程产出固定版本和测试证据，审查线程针对该版本提出意见；返工回原编写线程，复审回原审查线程。

发言结束、提交候选结论、审查通过和目标完成是不同事件。现有 `FINAL:` 前缀仍按既有契约登记候选，由 Host 定版；后续升级为结构化动作，不能仅凭文本前缀判定完成或交付。写审交付须结合版本、测试和验收条件核对；实施RFC明确兼容转换，不改变旧候选记录的含义。

每条审查意见记录稳定问题编号、级别、文件位置、版本及修复次数。对 SwarmMind 自身遵守同一意见两次未解决就请 Hana/用户裁决的规则；其他项目设置明确的轮数、时间和调用预算。耗尽或不确定时保留进度并暂停。

跨机审查必须明确代码基线、提交/补丁及哈希；产物中继不等于自动仓库同步。代码改变后旧通过结论失效。现有 Work 固定步骤模型需兼容新增的循环阶段记录，不以重派已完成步骤实现返工。

## 7. 本机与中心的边界

客户端与中心复用会话路由、协作、决策、预算和状态推进的共享模块，差别是目录范围和执行后端。客户端调用本机执行器，中心通过客户端连接委派；共享模块不意味着必须统一存储文件、进程或凭据。

每个空间具有固定归属：本机创建的由该客户端管理，中心创建的由该中心管理。本机空间只使用本机成员；需要跨机时明确引导创建中心空间。首版不做透明迁移、双主或断网自动接管。接入中心不会自动上传全部本机会话或开放全部 agent。

跨域换目标首版默认新建空间与原生线程，显式关联原目标并交接必要摘要/材料。后续复用健康旧线程须先暂停旧归属、校验节点绑定和所有权、保证同线程全局单写者；未经该交接流程不得把任意原生ID直接绑定到第二个可写空间。摘要交接有损时明确记录。

中心断开时，本机空间照常；中心空间暂停新增协调，已经被客户端接受的执行按既有规则继续或收敛，并在重连后依据平台记录及原生可查询事实对账。原生侧提供轮次ID/查询时利用该能力，不能假定所有CLI都支持；无法确认执行事实时进入needs_review。不能因为网络等待超时重复调用原生 agent。

角色与调用者位置分开：任何位置的外部 agent 均可持相应授权调用中心；“已登记为管家”的展示身份本身不授予额外权限。模型凭据、HOME 和原生会话材料保留在执行节点；当前中心可读取转发内容，不宣称端到端加密。

## 8. 精简、保留和扩展

| 方向 | 决策 |
|---|---|
| 精简概念 | 会话/协作空间为工作入口；任务与工作单退到执行详情 |
| 精简决策 | 统一决策服务语义，旧工具留兼容适配，避免两套候选来源和降级策略长期漂移 |
| 精简接入 | 发现agent后引导接入，创建会话时绑定环境；日常不重复填写命令行参数 |
| 保留基础 | 幂等、离线投递、结果仲裁、进程治理、权限、产物校验和审计继续服务主线 |
| 扩展核心 | 原生会话、群成员会话绑定、本机完整协作、中心内置有限流程、MCP双范围同义能力 |
| 扩展日常 | 问题与版本记录、暂停恢复、人工接管、额度等待、活跃空间保留策略 |
| 暂缓 | 完整A2A升级、P2P、多组织租户、agent市场、概率展示/复杂级联、通用工作流编辑器、透明跨中心迁移 |

agent 发现分成已安装、配置可识别、执行可用、允许调用；只找到命令不能标为可用。现有手工接入继续支持。权限模式显式配置，不能为了工具可用自动升级权限。

## 9. 实施顺序与验收门槛

| 阶段 | 可交付结果 | 必须实际验证 |
|---|---|---|
| A 会话基础 | 本机会话与轮次，Codex/zcode适配，REST/MCP | 明确ID两轮续接、A/B隔离、取消/超时、权限限制、重启与不确定窗口 |
| B 本机完整协作 | 独立客户端群聊、决策、手动/有限内置流程及外部管家接入 | 不启动Hub，完成讨论和编写审查；反馈回原线程、版本门禁、预算停机 |
| C 中心统一协作 | 全网目录、远程会话、中心空间和全网MCP | Hub机器无agent且无外部管家，通过网页与jev/明确规则跨双机协作；外部MCP另测一遍 |
| D 日常产品化 | 三入口、接入检测、双端一致交互、恢复与归档 | 双端同组件对照截图、配置/MCP检测、断网恢复及实际多轮使用 |

网页与MCP的最小入口随A–C同步提供；D完善日常体验，不把可用界面全部推迟到最后。新增管理REST同批提供MCP并登记SPEC映射，人工专属凭据操作沿用显式豁免。

现有已实现功能继续复用，不为符合阶段顺序删除。会话内核正在开发的文件不能直接当作已验收；每阶段按仓库独立测试循环与SPEC基础DoD验证，真实模型/异构双机与fake测试分别记录。

### 10.1 双端页面与形态对照

双端顶层导航同为会话、协作空间、资源；设置/诊断为辅助入口。以下“页”可为路由页或同一资源页的子页，但责任不可省略。同类新建/编辑用居中表单弹窗；详情从列表进入独立详情页；事件/执行明细采用右侧抽屉。字段同序、按钮同义；范围差异使用只读说明，不另造另一套交互。

| ID / 页面 | 客户端 | 中心端 | 关键字段与操作 | 无数据/异常出口 |
|---|---|---|---|---|
| P00 初始化与登录 | 本机主人初始化/登录，标明本机范围 | 中心管理员初始化/登录，标明中心地址 | 初始化凭据、登录、退出；不把管理凭据放MCP | 凭据错误可重试，服务不可达可检测；初始化和接入操作不触发agent执行 |
| P01 会话列表 | 本机会话 | 本中心管理的远端会话；不自动收集客户端私人历史 | 标题、agent、机器、工作区摘要、状态、最近轮次/活动；搜索/状态筛选、新建、继续、查看归档 | 无agent引导P05；无会话提供新建；远端离线保留记录并说明 |
| P02 会话详情 | 原生绑定在本机 | 通过路由展示对应客户端绑定 | 对话输入、轮次状态、答复、执行/权限/文件入口；继续、取消本轮、关闭会话、查看原生绑定 | 忙时显示排队位置或明确拒绝；材料丢失进入不可恢复提示，不能静默开新线程 |
| P03 协作空间列表 | 只含本机空间 | 只含本中心空间 | 目标、策略、调度方式/负责人、阶段、等待原因、最近活动；新建/打开、归档筛选 | 空态解释讨论和写审；没有可用成员引导P05/P06 |
| P04 协作空间详情 | 本机成员、会话、阶段 | 获授权开放的跨机成员、会话、阶段 | 目标/验收、成员与线程、当前执行者、讨论、阶段、问题/版本/测试、结果；发消息、指名执行、暂停、恢复、接管、提交候选、结束、归档 | 等待原因直接展示，操作受当前负责人和状态约束；不能仅发消息就隐式全员执行 |
| P05 agent目录与接入 | 扫描本机、手动登记、编辑/检测、允许本机调用/允许中心调用 | 只读汇集各客户端开放能力；申请刷新/定位来源，不装agent、不写远端HOME | 名称、类型/版本、路径、工作区、配置引用、权限、会话支持、检测与开放状态 | 扫描零结果允许手动；未登录/权限不足指向本机修复；服务器不替远端冒认健康 |
| P06 机器与连接 | 本机状态、可选中心连接配置、连接/断开与开放能力清单 | 节点在线/离线、能力与负载、接入向导、停用接入 | node身份、中心地址、证书身份、最近连接/错误；向导生成材料与重连 | 本机未连中心为正常独立态；中心无节点仍可管理并引导接入 |
| P07 MCP接入 | 生成本机调用配置、人工授权、本机宿主自动接线 | 生成中心调用配置与PAT操作入口，面向外部机器 | 详见第12节；统一分区/字段顺序，明确配置在哪台机器使用 | “已生成/已写入/已验证”分别显示；任何失败保留可复制的修复建议 |
| P08 协作与决策设置 | 本机jev、默认策略、可选本机管家/MCP绑定 | 中心jev、默认策略、外部管家接入说明和逻辑标识；无安装管家要求 | 决策端点/模型/密钥引用、候选测试、策略预算、选择默认管家；保存/测试 | jev未配置仍可手动；不把默认管家设置等同空间接管 |
| P09 执行与异常诊断 | 本机执行记录、轮次、进程/文件/日志摘要 | 中心派发与结果、节点等待/幂等/核对信息 | 从会话/空间下钻，关联ID、错误、时间、输入版本、证据与核对动作 | 结果不确定显示needs_review和证据；日志已清理保留必要恢复引用 |
| P10 设置与维护 | 数据目录/保留策略、通知、版本、服务配置、凭据维护 | 同类维护及PAT列表/撤销、节点接入凭据维护 | 查看、编辑、校验、保存，提示热生效或需重启；备份/恢复按现有已支持能力展示 | 不提供尚未实现的维护按钮；配置保存失败保持原值；危险动作说明具体影响 |

**共通交互契约：** 保存中防重复提交；表单校验失败定位字段并保留草稿；刷新不清空输入、不跳滚动、不关闭展开区；迟到响应不得覆盖新页面状态。错误面板给原因、影响、下一步、追踪ID和时间；敏感值不进入日志。导航跨本机/中心必须显示当前范围，不能悄悄改变提交目的地。

### 10.2 首次进入与默认落点

新客户端：P00→P05发现/接入→P02首轮会话；页面始终可选“独立使用”而不填Hub地址。要由外部agent发起工作时转P07；要多agent协作转P03。新中心：P00→P06接入客户端→P03/P01；无需安装任何agent或指定管家。已有数据默认落到最近使用的会话/空间列表，展示需要处理的等待与不确定结果。

## 11. 关键表单、动作与状态

| 对象 | 最小输入与校验 | 提交结果与编辑边界 |
|---|---|---|
| agent接入 | 显示名、适配器、命令绝对路径、固定参数、已有工作区、配置HOME引用、权限模式、超时；高级环境逐项允许 | 先保存登记再显示检测状态；扫描只发现不自动开放、不读取导出模型密钥；本机调用与对中心开放分开开关；改绑定不影响旧会话事实，续聊不兼容时阻止并解释 |
| 新建会话 | 标题可选；agent必选，中心补机器；授权工作区；首轮输入必填；展示模型配置引用及权限，不要求用户粘贴模型密钥 | 返回平台会话定位与首轮状态；原生ID创建成功后展示；响应丢失按同键查回；会话创建/首轮边界由RFC定义但不能留下不可识别副作用 |
| 继续会话 | 输入必填，显示绑定与当前状态；不让普通输入修改原生ID或执行目录 | 新轮次关联原会话；提交重试不重复执行。忙时采用有界可取消队列；队列满明确拒绝；新建不同会话不绕过工作区互斥 |

| 暂停/恢复 | 暂停无需篡改计划；恢复展示预算、依赖、负责人、版本变化 | 暂停只阻止新增派发，在途结果照收；取消在途另点“取消本轮”。阻塞未解除不能恢复；租约恢复/接管后仍须显式恢复，不由结果回流擅自推进 |
| 结束/归档 | 完成要求满足验收、无未收束尝试；放弃要填写原因 | 结束产生只读交付/放弃报告；“归档”是列表收纳，不删除会话材料、不取消任务，只对已结束/关闭且无在途对象开放；完成对象不原地重开，继续需求可新建关联目标 |
| 接管 | 显示当前负责人、最新任期与在途执行；用户确认交接影响 | 原子更新归属，旧任期后续写入拒绝；冲突要求刷新；接管不重跑任务、不扩大身份权限；切回内置/手动也适用 |

会话状态至少能区分：创建中、可继续、执行/排队中、待人工核对、不可恢复、已关闭；轮次至少区分排队、执行、完成、失败、已取消、不确定。空间至少区分待配置/待管家、可运行、运行、暂停/受阻、待核对、已完成/已放弃。状态原始值由RFC统一，不直接复用现有任务状态拼凑。等待原因（节点离线、额度、权限、预算、工作区占用等）独立展示。

**关闭会话不是删除历史：** 存在在途时禁止关闭并引导先取消/等待/核对，关闭后拒绝新输入。退出网页、断MCP连接不等于关闭会话。

**已有TUI会话：** 首版保证平台创建线程续接；导入现有TUI线程不是必备交付。若提供导入，必须核验节点、适配器、工作区、原生ID和权限，要求用户先停止原写入者；不能承诺对平台外进程自动加锁。检测不到独占状态时不显示“已安全独占”。

## 12. MCP接入页（P07，双端必备）

### 12.1 用户任务与页面布局

用户要完成的是“让选定外部agent可靠调用本机或全网能力”，不只是下载JSON。两端按相同顺序呈现六个稳定分区：①范围与拓扑；②调用环境；③人工授权；④配置预览/应用；⑤分层验证；⑥维护与故障。它是资源下的明确子页，有来自agent详情、管家设置和首次接入的深链。

| 分区/字段 | 客户端语义 | 中心端语义 | 验证与操作 |
|---|---|---|---|
| 目标范围（只读） | 当前本机node与能力范围 | 当前中心及其开放的节点能力 | 顶部固定显示“调用本机/调用中心”；切换入口重置旧配置/检测状态 |
| 外部调用者在哪里 | 默认与Node同机；跨机经已配置的安全转发访问 | 默认另一台机器；也允许同机 | 图示MCP适配进程运行在调用者机器，它通过API访问Node/Hub；默认不开放Node公网管理端口 |
| 宿主类型 | 已支持宿主及通用手动接入 | 同一宿主选择 | 仅展示实测兼容格式；格式未知给通用参数说明，不能宣称已适配。MCP配置格式依宿主，不统一硬套JSON |
| MCP可执行文件路径 | **调用机器上的**绝对路径，默认仅在确认同机时可探测 | **外部调用机器上的**绝对路径，服务器路径不能自动代填 | 远端路径无法由网页校验存在；标“待外部验证”，允许手填，附当前版本构建/安装说明 |
| 服务地址 | 同机回环，或调用机可达的转发地址 | 外部调用机可达的HTTPS中心管理面地址，或已配置转发地址 | 明确127.0.0.1属于MCP进程所在机器；校验scheme与格式，服务器探测成功不代表外部可达；不提供不受限任意URL探测接口 |
| 授权状态/引用 | 本机主人授予的本机编排调用凭据，绝不使用local_token | 管理员授予的PAT，绝不使用admin_token或Web登录cookie | 显示实际权限/影响范围，不声称已有按agent细粒度权限；不默认填入或回显服务器保存的旧密钥 |
| 配置名称 | 默认区分本机实例 | 默认区分中心实例 | 同一宿主允许本机/中心并存，不静默覆盖同名已有条目；冲突可改名或显式确认替换 |
| 配置生成/应用 | 预览、复制、下载；仅本机可验证的支持宿主可自动写入 | 预览、复制、下载到调用者机器，不写Hub上的“宿主配置” | 预览无有效凭据时用占位符并标不可直接调用；复制与下载包含秘密时明确提示保存位置 |
| 最近验证 | 分层结果、时间、调用来源、权限与工具能力摘要 | 同左，附中心与节点可用性 | 连接验证与工作成功分开，不用“已连接”掩盖缺工具/无执行者 |

### 12.2 授权、管家与调度权分离

本机“授予MCP调用权”不应强制指定某个本机agent为管家；外部agent可仅作为普通调用者。当前本机prime_agent/prime_token门禁需要在W02显式改造：将既有编排授权与展示角色解耦，保留兼容迁移，不能靠把所有调用者假标为管家绕过门禁。

首版本机可复用单个可轮换的编排凭据，不承诺已经实现每调用者令牌隔离。页面必须说明共享该凭据的调用者影响范围、轮换会让哪些配置失效；按调用者独立签发为后续能力，不能显示虚假的逐客户端撤销按钮。中心沿用实际PAT权限模型；选择一个“只调用某agent”的展示标签不能代替服务端授权。

本机主人/中心管理员通过人工专属入口授权、换发、撤销。凭据操作不因新增MCP页自动向agent开放；沿用SPEC显式豁免制度，新增豁免在实施变更中登记。模型密钥与MCP调用令牌不同，前者不进入配置。

新凭据仅在创建/轮换的人工操作结果中一次展示；刷新后只保留引用/脱敏状态，不能重新取回旧明文。已有令牌可由用户在当前页面临时输入，退出/刷新不持久保留；无法找回时引导换发，而非暴露服务端密钥。包含明文的配置仅由本次授权/输入生成，页面不得自动将其写入持久浏览器存储、URL、诊断日志或埋点。

“设为默认管家”是可选偏好，不自动领取已有空间、不增加令牌权限；空间调度权通过显式领取/接管与任期控制取得。

### 12.3 配置内容与应用行为

现有stdio桥接方式是首版基线，不承诺Streamable HTTP/SSE远程MCP服务已存在：

- 本机后端参数使用 `SWARM_TARGET=node`、`SWARM_NODE_URL`、`SWARM_NODE_PRIME_TOKEN`；中心后端使用 `SWARM_TARGET=hub`、`SWARM_HUB_URL`、`SWARM_HUB_TOKEN`。具体启动配置按宿主适配格式输出，不将这些变量重命名为拟定API。
- W02完成解耦后，`SWARM_NODE_PRIME_TOKEN`承载不依赖默认管家声明的本机编排调用凭据；保留变量名是宿主配置兼容要求，不表示继续强制prime_agent门禁。旧配置迁移与回退要在RFC明确。
- 新会话/空间等工具随能力开发逐步装配；页面从实际工具发现结果显示能力，不把当前node六工具与hub工具差异隐藏成“已完全对等”。版本不满足必需操作时列缺项并阻止标记“完整接入”，提示升级哪一端。
- 页面生成配置不安装二进制、不自动给外部机器开放网络、不自动为外部agent注入配置。提供复制指令与最短验证提示词；调用机器缺适配程序时明确列前置步骤。
- 本机自动接线：先识别已验证的宿主版本/文件位置，展示目标文件、配置名、差异和已有条目影响，用户点击应用后备份并原子合并；只改目标条目，失败保留原文件。未知布局、不可写或非法格式退回手动，不能改造用户整个配置文件。现有zcode接线是可复用基础，不代表所有宿主都支持。
- 撤回自动接线只撤销本次改动；原配置此后被用户改动时不盲目恢复旧整文件，展示冲突、引导手动处理。中心网页不尝试写外部机器文件；本机工具代写需后续明确支持。
- token轮换即使自动写配置失败，已生效的新授权也不能假装回滚成功；分别展示“授权已换发/配置未应用”，在本次结果中提供恢复材料。授权变更与宿主配置写入的跨文件一致性由RFC细化并测试。

### 12.4 分层验证与可复制提示词

状态不是单一绿灯，而是以下独立检查项；未运行显示“未验证”，任一层结果不推断下一层。首版不提供联网调用者的全局“在线列表”，stdio宿主进程空闲不等于断线。

| 层级 | 谁在何处检查 | 成功意味着什么 | 失败显示 |
|---|---|---|---|
| V0 配置就绪 | 网页/服务端 | 配置语法、必填项、范围一致；同机可检查本地程序 | 缺路径/凭据/格式/危险拓扑，指向字段 |
| V1 调用机连接 | 外部MCP进程实际访问Node/Hub | 调用机地址可达、TLS身份通过 | DNS/拒绝连接/证书错误/转发缺失；不建议跳过TLS验证 |
| V2 授权有效 | 目标服务鉴权 | 当前凭据被接受，权限符合该调用 | 401过期/撤销或403未授权，转人工授权入口 |
| V3 宿主工具发现 | 外部宿主完成MCP初始化和tools/list | 所选宿主实际加载了适配进程并发现所需工具 | 宿主配置未重载/启动失败/协议或版本缺项，不能靠服务端自测冒认 |
| V4 无副作用查询 | 外部宿主调用目录/状态工具 | 本机/全网范围正确，返回来源可核实 | 无节点/能力与“连接失败”分开，目录为空也可以接入成功 |
| V5 可选执行验证 | 用户明确发起一项低影响任务/会话 | 指定agent完成并可追踪结果 | 区分接受/执行/工具权限/工作失败；会消耗模型额度，默认不运行 |

页面默认只保证自身可执行的V0；服务端的网络/鉴权自测仅标“服务端视角”，不能直接标外部V1/V2。V1–V4可通过提供的调用机诊断程序/外部工具回执获得；首版若没有可验证的回执通道，明确显示“等待外部验证”，允许展示用户手工反馈但标为“用户确认”，不能伪造自动检测成功。

后续诊断回执须由服务端鉴权并与目标、配置修订、调用来源和本次检查关联。普通REST查询日志只证明被调用，不证明宿主完成tools/list；旧版本或旧令牌的回执不能点亮新配置。更改地址/令牌/宿主格式/目标范围使相关状态失效，历史结果保留时间与来源可查。

页面必须提供可复制的自然语言验证提示词，例如：

> 请通过我配置的 SwarmMind MCP 列出当前目标的机器与agent，明确它是本机还是中心范围；只查询，不创建任务、不启动模型工作。若工具不可用，报告缺少的工具或错误。

执行验证另行提供：选择用户指定的测试agent和独立工作区，说明可能调用模型，确认后才提交；不得自动修改项目、执行发布或用重复派发“验证连接”。

### 12.5 MCP验收要点

两端分别跑通“人工授权→生成正确调用机配置→外部宿主tools/list→无副作用目录查询→可选执行”，并证明：本机与中心配置可以并存；管理凭据未泄露；错误回环地址不会显示外部已验证；未知宿主可手动接入；自动合并不毁原配置；token换发/撤销使旧调用明确失效；刷新页面不恢复旧明文；无管家也能接入和调用；中心无agent也能输出有效配置。完整用例见AC05–AC10。

| F05 群讨论 | P03给目标/验收→讨论策略/预算/调度方式→选参与者或等待管家选人→显式启动→指名成员续接→候选结论→核对/结束 | 形成可引用结果，保留各成员线程与决定 | 读消息不触发轮次；jev失败等待手选；预算耗尽暂停；候选不自动等于交付 |
| F06 编写审查 | 配置编写/审查成员与版本交付→编写原线程→冻结版本/测试→审查原线程→意见编号→返工→复审→验收/结束 | 必须修清零、版本匹配、测试证据合格、无在途，出交付报告 | 两次未解意见按项目规则上报；新版本使旧通过失效；代码同步失败进入受阻 |
| F07 人工干预与接管 | P04暂停新增派发→查看在途/任期→取消或等待→人补充目标/预算/成员→显式接管/恢复 | 唯一负责人推进，旧任期动作拒绝，在途结果仍记账 | 接管响应丢失可查回；冲突刷新，不重新派发；权限请求由有权的人处理 |
| F08 断连与恢复 | 网页/MCP断开→后台保留执行→重连查原会话/空间与轮次→按执行事实核对→显式恢复协调 | 已确认输入不重复执行，原会话定位不变 | HTTP空闲不判管家死；租约到期暂停；无法证明结果则needs_review |
| F09 完成、放弃与归档 | 查看候选/测试/验收与在途→完成或填写放弃原因→生成报告→归档 | 报告含结果、版本、未完成项和证据；活跃引用不被日志清理破坏 | 有在途不能完成/归档；放弃空间也不能假装取消已发生副作用 |
| F10 授权维护 | P07/P10查看授权影响→人确认轮换/撤销→重配外部宿主→重新V1–V4 | 旧凭据新请求失效，新配置结果可核实 | 无法恢复已撤销密钥；不自动取消已接受执行，结果按既有契约记账 |

所有“发送/启动/恢复/接管/结束”动作要有稳定请求标识与可查询结果；网络失败优先查原请求，不以新标识反复创建。已有REST/MCP不能表达的生命周期动作在实施RFC补齐，不能以操纵Task字段代替。

## 14. 异常与恢复矩阵（E）

| ID / 触发 | 用户看到的原因和影响 | 可执行下一步 | 系统禁止行为 |
|---|---|---|---|
| E01 未安装/路径错误/版本不支持 | 区分未发现与不可执行、列检测时间 | 手填正确路径、安装/升级后重测 | 扫描命中就自动开放 |
| E02 原生账号/模型额度/网络失败 | 区分模型不可用与平台路由失败；不展示密钥 | 在源节点修复登录/网络或等待额度，确认原轮状态后继续 | 自动替换模型或无界重试 |
| E03 MCP程序/宿主加载失败 | 说明调用机程序路径或配置格式问题，不说服务离线 | 重装调用机桥接程序、重新加载配置、查V3 | 用Hub本机路径冒充外部有效路径 |
| E04 MCP地址/TLS/授权失败 | 分别展示V1/V2错误、检查视角和目标 | 修正转发/地址、验证证书身份或人工换发授权 | 把服务端自测标为外部通过、跳过TLS |
| E05 MCP工具缺失/版本混跑 | 列实际发现工具和必需缺项 | 升级对应Node/Hub/桥接程序，或仅用已验证子集 | 把缺能力当成功，静默退回无会话任务 |
| E06 节点离线/中枢断连 | 接受前排队与已开始执行分别展示，列有效等待期限 | 等节点恢复、在明确未执行时取消排队；本机工作另建本机空间 | 相同原生输入到别处盲重发、跨域自动接管 |
| E07 线程忙/工作区冲突/外部TUI占用 | 显示锁定范围与待处理输入，外部状态未知要直说 | 等待、取消排队、停止外部写入者或改用独立工作区 | 通过新建会话绕过代码写入互斥 |
| E08 原生ID丢失/返回ID不一致/配置不兼容 | 不能确认是原线程，保留平台与节点证据 | 人工核对、修复绑定材料，或显式新线程交接 | 自动resume latest、把新线程标成旧线程 |
| E09 超时/取消/重启结果不确定 | 分清取消请求已接受与原生执行已停止、外部副作用可能存在 | 查事实/进程治理结果；有证据再继续，未知needs_review | 把CLI退出/网络超时直接当任务未执行 |
| E10 jev失败/非法候选/无候选 | 无有效选择，不增加成员和执行量 | 手选有效成员、修复决策配置；成员都不可用时等待 | 默认换模型、扩大范围或自动全员唤醒 |
| E11 预算耗尽/意见重复未解/验收争议 | 保留已完成工作与未解决项，暂停原因明确 | 人工裁决、调整预算后显式恢复、放弃并报告 | 充值预算即自动续跑、无限返工 |
| E12 工具权限询问/拒绝 | 区分平台授权与原生工具权限；不支持交互的适配器明示 | 有权用户在支持通道批准或源端处理；不支持则暂停/受阻 | 管家自批提权、自动换yolo、假装有权限待办闭环 |
| E13 材料/版本/产物不可用 | 指出版本不匹配、校验失败、源离线或超限 | 恢复源材料或显式提交新版本重新审查 | 用旧通过结论交付、自动重跑上游 |
| E14 租约过期/重复接管/服务端状态冲突 | 当前负责人/任期和请求冲突说明 | 刷新事实、重读空间、显式CAS接管 | 旧管家复连后自动抢回、在途结果触发新负责人之外的执行 |
| E15 落盘失败/配置应用失败/历史缺口 | 分别显示“未保存”“授权已生效但配置未写入”“历史已裁剪” | 保留输入与请求定位，查保存结果、手动修复/恢复材料 | 失败仍显示成功、损坏记录当空表静默遗忘、无限补拉触发派发 |

取消、超时与清理不能推导任意外部副作用已回滚。任何不可恢复状态必须保留证据与人工处理路径；页面错误不会扩大执行授权。未知错误归入受阻并提供追踪ID，不自动选择高风险恢复。
