# AgentBridge 实测报告（2026-10-20，Mac mini 本机）

> 实测对象：AGNTCY SHADI AgentBridge v0.3.0（源码编译）+ shadictl v0.2.0（源码编译）
> 方式：源码构建 → in-process demo 三场景 → 真实 codex CLI 接入尝试（端到端委派卡在 DID 身份派生，SSH 私钥操作需人工审批，如实记录）

## 部署重量（首次接入摩擦）

- Rust 工具链 + cmake（aws-lc-sys 构建依赖）+ 包名带 agntcy- 前缀（`-p agentbridge-cli` 报错，实为 `agntcy-agentbridge-cli`）
- 编译 2 分钟（M6）；无预编译 release 二进制（release 只有 changelog，无资产）
- 认证强制 DID：共享密钥被明确拒绝；须从人类身份源（SSH/GPG Ed25519）派生 agent DID，多步流程
- 远程可达 listener 强制跑在 shadictl --net-block 沙盒内（网络默认封锁，白名单放行）

## 能力确认（亲眼所见/文档代码确认）

| 能力 | 状态 |
|---|---|
| CLI profile | claude-code / copilot / codex / cursor-agent / goose / opencode / generic-stdio，均为 spawn+stdin/stdout 的 execute_prompt 模型 |
| 任务存储 | **InMemoryTaskStore**（文档明示）：无持久化、无离线信箱、无崩溃恢复 |
| 任务模型 | execute_prompt 单发单收（prompt 进 text 出）：无超时治理、无投递窗口、无幂等去重、无 env/参数白名单、无 stdin（一次性 prompt） |
| 结果 | response text 纯文本，无产物引用、无结构化错误、无完整答复/摘要区分 |
| 协调编排 | proposal→vote→converge 多轮收敛 + 上下文交接（msgs/files/artifacts 序列化）——编排层特色能力 |
| 身份 | DID+签名信封（unsigned→AUTH_REQUIRED），密码学身份强于 token |
| 沙盒 | 远程可达 listener 强制 net-block 沙盒（安全设计，值得吸收） |

## 对比结论（对照 SwarmMind 契约）

AgentBridge 强在：编排模式（多 agent 收敛/交接）、DID 身份、A2A 原生、AGNTCY 基金会背书。
AgentBridge 缺在（=SwarmMind 差异化立足点，全部经实测/文档确认）：
1. 可靠交付：无持久化任务账本、无离线信箱、无三段 Ack、崩溃即丢任务
2. needs_review：无不确定执行的人工核对语义
3. 执行治理：无超时/白名单/干净 env 基线/投递窗口
4. 结果协议：纯文本无产物引用
5. 部署：Rust+SLIM 节点+DID 链 vs 我们 Go 单二进制+token

诚实备注：以上缺项基于其公开文档与代码结构，AgentBridge 迭代快（4 天前发版），正式竞争分析需按版本复核。差异化必须在「交付可靠性+接入摩擦」上实测对比成立，而非功能清单。
